# R3-A 下一轮：沟通、责任与目标共用事件证据

2026-10-31，依据 [18 窗口冻结验收](../milestones/r3a-phase-contract-validation-2026-10-31.md) 制定。**2026-11-01 状态更新：步骤 1–3 已实现并进入本轮离线交付，步骤 4 的目标连续性及完整位置知识仍待实施，真实复验未开始。** 当前已交付范围见 [事件证据接口](../../documentation/cognitive-event-evidence.md) 与 [本轮记录](../milestones/r3a-event-evidence-2026-11-01.md)。没有追加付费采样，单一世界状态、来源分级和 Node/Python 权限保持不变。

## 目标与归属

喵呜可以自己决定研究、告知、等待、换事或放下。程序需要准确回答：发生了什么、谁实际知道哪些内容、哪些约定由谁接受、当前目标的哪项条件满足了。丰富地区和活动时，应复用这一层证据，而非每增加一个地点就改一套认知提示。

沿用现有 `root_outcome_id → actual_result → memory_frame → continuation / goal_bindings / development` 链，不另建世界数据库或第二个事件总线。补足共享合同、受权限限制的事实投影和两端一致校验；自由感受继续保留为个人解释，不能反向改写公共事件。

## 沟通内容和送达凭据

复用 `cognitive-social`、`cognitive-choice-catalogue`、`cognitiveActualResult` 与已有消息编号。

- **完成通知**只声明某任务完成；选项名称也明确为通知完成。它不满足“把亮度和蓄光告诉某人”。
- **结果摘录**从已保存的完成结果中选择可公开的字段；携带结果根、发生时间、对象、条件、数值、单位和范围。测记保留“包含环境与时间变化、单次记录不能证明因果”的限制。物品产出、交付与观察使用各自登记的字段，不能复制整份私有上下文。
- **实际送达**冻结发送者、接收者、消息编号、正文／结构化片段及其哈希、来源摘录编号和送达时间。原结果有某字段，不代表消息公开了该字段；来源编号也不代表接收者自动读取来源全文。
- **收到、理解、接受**各自有事实。仅送达不能表示对方读懂、同意或作出承诺；回应与约定沿用原社交执行器。
- **后续与目标**引用实际消息中公开的字段集合。把“告知完成”“告知指定结果字段”“物品交接”分别建成可核验条件，禁止只按 `share` 动作完成便算履约。

事实叙述由有限、可核验的事件片段提供；模型保留个人感受、未来打算与主观疑问的空间。不能只用关键词过滤器声称验证了任意自然语言，也不能增加一轮模型自评分就当作客观证明。应首先消除产品显示、事实记忆及完成判据对自由文本的依赖，再用真实模型审查个人解释是否仍漂移。

## 邀请、身份和责任

复用已有 `source`、`social.commitments` 和 `life_motivation`，新增依据校验，不建立第二份承诺状态。

1. 外部正文署名是来源声称的身份；保留 `reported` 与 `no_reply_address`。只有实际镇内身份绑定或经过核实的路由才能指认消息发送者。角色仍可以自行向一位已知居民确认。
2. 选择 `invited` 引用真实请求来源。选择 `accepted_obligation` 还需明确引用当前主体参与、已接受且未失效的约定与条款版本，并核对所选动作在该约定的履行范围内；不能任选一份无关约定凑依据。
3. 将依据规则登记在共享合同。Python 提供候选证据并校验，Node 采用前再次核验当前条款。无依据时要求原有一次修复或保留精确失败；程序不替角色选成其他动机。
4. 现有执行器将无依据义务降为 `unknown` 的兼容保护继续保留；旧存档原样保留。但新协议需在选择端暴露不成立的归因，不能把执行器降级当成个人解释正确。
5. 邀请、接受、延期、撤回、过期及条款修改全部走原公共结果。新证据仍不能自动增加兴趣、自主选择次数或关系成果。

## 目标连续性与位置知识

目标的稳定 ID 对应本人想达成的条件；方法选择是其中一次尝试。方法条件和用途只在目标确实要求它们时才进入完成判据。例如“在有罩夜间完成一次测记”应保留条件；“发出指定读数”应绑定读数与接收者；“了解罩片是否更好”属于开放研究，单次测记不能自动完成。

沿用 `goal_bindings` 和共同结果，不以近似文本匹配直接合并或结案。为继续、重新计划、放下和已满足设计明确操作；已有目标更新保留 ID 和历史，实质新目标才新建。无进展、等待回复、条件不足、到期复查和实际失败分别记录。复查时钟与失约截止分离，避免模拟时间跳跃把所有未做的愿望都判失败。

人物位置从亲见、真实消息和带时间戳的共享事实投影。可联系名单与已知位置分开；曾经在苗圃、以苗圃为家、名字类似地名，都不能推出现在在苗圃。过期位置显示时间与不确定性，角色仍可选择探索。

## 免费验证矩阵

| 类别 | 必测反例与正例 |
| --- | --- |
| 内容边界 | 完成通知没有读数；指定读数实际摘录；旧读数与当前数值不同；只公开部分字段；任务根错误；私有感受不可被来源引用自动公开 |
| 送达与幂等 | 送达失败、接收者离开、重复回包、重启补反馈；发送一次、记账一次，不重做测记或重复消耗 |
| 来源与责任 | 外部署名冒充居民、真实邀请但未接受、已接受本人的约定、他人的约定、无关条款、过期、撤回、延期未确认、晚到响应 |
| 目标连续性 | 同目标跨方法；方法相同但条件不同；备用与实验用途不同；已完成仍挂起；近似目标反复新建；等待后跨夜；主动放下与失败分开 |
| 空间知识 | 同地亲见、别人告知位置、旧位置、未知位置、只有联系权限；不读取其他角色私有想法 |
| 扩展性 | 用另一种现有方法的结果验证同样的通知与完成判据；不写死归途灯名称、数值或角色名字 |

每条至少覆盖 Node 权威结果、Python 提案检查及两端接缝；关键恢复病例使用真实子进程和实际任务结算，不仅断言提示字符串。不同语言的验证使用同一合同与相同反例。全部通过后再允许新版本有限真实实验。

## 后续管线保持

R3-A 出口通过后进入 R3-B：喵呜与两名居民各自有需要、事务、可知信息和行动时间，允许接受、拒绝、延期与不回复，验证真正双向的共同生活。R3-C 再迁入成熟的地区与创作、休闲、探索机制，让新增地形产生可比较的机会与后果；R3-D 完成正式接线、恢复与运行成本，之后才是 R4 自然跨日和 R5/R6 的形象、表达与实体设计。

地图概念可以继续准备。长期兴趣、角色愿望、奇幻感和美术仍须单独验收，固定归途灯矩阵只检查底层可靠性，不代表完整产品生活已经成立。
