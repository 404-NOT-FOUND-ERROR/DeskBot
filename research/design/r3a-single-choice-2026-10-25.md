# R3-A 单次选择、确定性绑定与复验

承接 10 月 23 日整体核对及未通过的两批记录。本轮首先修复程序，再做有限真实实验。正式人生存档不用于实验，正式持续认知仍关闭。

## 改动与不变项

角色仍通过 Asamana 的需要、记忆、人格与关系选择行动。新适配合同只让它选一次：具体活动、目的、关联事项、如何对待已完成步骤、联系对象与表达。程序把明确选择绑定到现有 Node 执行器；不再调用另一个模型重复抄活动、用途与问题编号。

`current` 明确引用当前本人事项；`selected_activity` 明确选择验证本次活动。角色主动选择复查步骤或结案后，程序从所选事项读取原目标和原证据。没有证明就拒绝客观完成；程序不替角色选择满意、放弃或新的目标。

生产的活动编号取同一次明确方法；实验用途引用同一次明确问题，数量为一次活动产出；备用最多一批，真实自用/已接受交付按已有条目绑定。不推断缺失的意图，不因编号错误改选另一种行动。原材料、时段、冷却、重复联系、私有知识与事实记忆校验继续执行。缓存历史上下文仍保留旧合同。

上下文去掉人格、选择、编译之间的重复副本；不新增模型摘要或裁判。配置补齐上海天气的持久文件，启动默认不做付费模型探测，连接展示采用真实来源调度状态。

## 验证与付费登记

先测旧失败反例、跨语言实际 worker 的零网络执行、后端全套、Python、前端构建。通过后冻结源文件、版本哈希、场景与调用上限。

真实复验仍为 `resources-1-off/on`、`invitation-3-off/on`，每例五个窗口，共二十个。场景、库存、人物和跳时策略沿用原夹具，不同时引入地图与新活动。先运行原 resources 对照的两例；仅工程和语义审查无关键错误时，同版本继续另两例。每次最多一个语义修复，累计最多 **170 次 API 调用**，单次调用仍有输出长度与预算记录。最终协议/执行错误立即停止整批，不换场景、不重采样，不自动追加付费版本。

沿用用户已授权的虚构人物、世界、来源和实验记忆范围，排除正式聊天、传感器和私有存档。记录失败、修复、所有费用与响应；严格缓存回放不得接入网络。

每个进入的窗口都计入分母。至少二十个同一冻结版本的后续观察窗口，至少 80% 有实际推进，或有具体依据的改法、延期、个人收束/放下；同时检查首次采用率、错误物理解释、等待理由、产物用途、记忆事实和无依据重复。空转、重复观察或生产不能因接口合法就算有效生活；休息和不行动也不能一律算失败。分开报告工程完成与语义合格，不自动等同达标。

这轮不运行其他居民的自主回复，不证明多人生活、自然跨日、稳定兴趣或正式环境。合格后才进入 R3-B；R3-C 再引入新地区/机制与兴趣对照。新旧版本窗口不累计。

## 请求格式失败后的预登记修订

冻结 `17fb2d6ecfb4` 首例第一轮停在决策请求：DeepSeek 返回 HTTP 400，JSON mode 的提示中缺少明确的 `JSON` 字样。两次前置调用返回，第三次被接口拒绝；尚无行动或后续窗口完成。原批停止，记录与不确定费用保留。

这是新选择提示的传输合同遗漏，离线模拟此前未覆盖 provider 的这一限制。补上明确 JSON 指令，在预算入口与实际 worker 本地测试加入前置检查，并缓存失败请求供后续严格回放。原失败批没有完整终止响应缓存，不能声明它已通过严格回放。

原本计划不自动追加冻结版本；此次明确修订为允许**一次请求格式修正版**，仍使用四例原起点与指标，不挑选输出。新版本至多 167 次，与已占用三次合计仍不超过 170 次。先检查 resources 两例，再决定是否续跑 invitation 两例。此修正版如再遇最终错误则停止，不继续追加付费版本；可继续修本地代码，但不将未复验修正写成通过。
