# R3-A：具体选择、沟通目的和事实记忆复验

本轮承接用户“好，继续完成”。只使用原先批准的隔离虚构人物、世界及实验记忆，按既有“不限制金额，节省着用”授权；不读取或发送正式对话、传感器和正式人生存档。先完成本地工程与免费回归，再运行以下固定批次。

## 本轮问题与实现

- 旧的“同一研究出现新结果”范围太大：装罩不能作为重新询问同一批水用途的理由。新沟通按收件人、具体目的和实际条款记账；口头问需水与正式送水提议共用同一目的。无关任务、改事项名、过期或普通时间漂移不解锁；真实回复或实际条款变化才重新提供选项。
- Node 从当前实际能力生成选择目录，模型选择具体活动及用途、对象、收件人与语义，不再重复填写相互关联的编号。Python 确定性绑定；Node 对照冻结目录和当前世界再次验证。保留 act=false、换事、暂缓、个人收束等选择，目录不规定行动顺序。
- 继续原问题时，已证明的小步骤归档；未完成目标不能改成容易的目标。实验产出必须绑定尚未完成的本人研究步骤。普通备用、自用和已接受交付分别限量。
- 本轮实验交流正文来自所选语义与可核验记录，不再允许自由 question/intention 夹带事实。感受记忆选择关注项、情绪和打算，全部事实由执行器保留；不是靠关键词判断任意自然语言真假。
- 保留旧合同与旧批次证据，旧记录不改写成新版本结果。没有编号的历史留言仍可被感知，但不伪造可回复编号。

## 预注册验证

1. Python 适配器回归；真实 Python + Node 本地模拟模型串联；四个场景的全部可用选项逐项验证；反例覆盖目的重复、无关变化、不同收件人、真实回复、过期、重启/显示记录淘汰、私有背包、指令篡改、旧存档兼容和记忆事实。
2. 保留固定 `resources-1-off/on`、`invitation-3-off/on`，每例 5 个窗口，共 20。第一对完成后人工检查，达标才运行第二对；不换病例，不重抽失败。每个选择最多原有一次修复。
3. 本批累计最多 170 次模型调用。协议/执行终止或严重事实错误即停；预算用尽停止，不自动加码。失败计入进入窗口的分母；未运行窗口明确列出，不当作成功。
4. 工程验收：20 个完整计划—结算—记忆—后续窗口；无物品/承诺伪造，无重复未回复同目的；至少 16/20 个窗口具有由实际条件支持的选择、推进、换法、休息、暂缓或合理个人收束。不能只按流水线跑通判定生活感。
5. 另报首答采用率、修复数量、每阶段调用/token/估算费用、完整窗口延迟。变化减少或费用下降不直接推断全镇日成本；受限表达不等于开放叙事能力提高。
6. 同版本严格缓存回放检查初末世界哈希、停止原因，零新增 API。模型结果和人工审查独立保存。若语义门槛未达成，R3-A 保持未验收，不推进 R3-B。

## 范围边界

这一轮只验单一个体的事项连续性。另两个居民不自主回复；其沉默不能记作拒绝。固定语义、有限情绪词表是本轮可核验接口，不是最终个性表达或完成的多人社会。R3-B 仍需双边回应、承诺、协作及各自记忆；R3-C 才引入更多地区、机制与兴趣机会。自然时间下的数日稳定性尚需后续独立观察。

实验冻结版本、最终结果与费用见对应里程碑文档和 `runtime/r3a-catalogue-20261025/`。本文件的上述标准在付费调用前确定。
