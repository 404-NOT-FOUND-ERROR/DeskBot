# 喵呜实体与造型设计约束

2026-10-07 · 第一阶段约束基线 v1 · 尺寸和制造参数待实测

初始喵呜使用 ESP 喵伴本体与旋转底座。后续探索最小保护与安装核心，再让主题外壳和配件围绕核心生成、制作和拼装。结构、美术、声学、运动与打印条件需要联合迭代，第一阶段先确定约束和验证顺序。

## 已知条件与验证状态

| 条件 | 依据与状态 | 设计要求 |
| --- | --- | --- |
| 无摄像头和现实行走机构 | 用户样机描述，软件合同一致 | 不设计视觉观测或现实走跳的承诺 |
| 一个左右旋转自由度 | 用户样机描述；软件已限制单轴 | 头部与身体留运动空间，其他虚拟动作分别表达 |
| 头部触摸和触控屏幕 | 用户描述的输入能力；DeskBot 尚未实机联调 | 可触达且有明确反馈，主题件不破坏工作条件 |
| 两个麦克风与声源方位 | 用户描述，照片和现有固件资料 | 保留经验证的开孔与声学通道，核验方向坐标及识别效果 |
| 地磁换壳识别 | 当前设计要求；签名及识别可靠性待实机校准 | 壳登记、磁性布局、未知签名与识别状态分别处理 |
| 扬声器与后部接口 | 用户图片、现有外壳及固件资料 | 出声、连接、拆装与维护窗口可用 |
| 当前小智固件 | 用户确认及项目审计 | 适配事件、输出、单轴控制与回执后再声明 DeskBot 实机闭环 |

软件目前的 yaw 限幅是控制策略，不能当成实测机械行程。磁识别属于待校准能力，不把历史 NFC 方案或额外轴当作当前样机功能。

## 身份和造型的层次

**个体连续性。** 角色标识、经历、关系、愿望理由和阶段历史保持相连。外形改变不创建第二个人生，也不清除已完成的事。

**实体约束。** 当前电子内核的安装、圆屏、声学、触摸、接口、旋转与维护条件要保留。具体尺寸、位置余量和连接基准通过实测进入设计。

**可变化特征。** 猫耳、胸前黄点、身体轮廓、装饰、主题材质和配件是初始设计内容。改变这些特征仍需保持设备功能；例如改变耳形要重新验证麦克风通道，而不以外观相似作为声学证明。

**跨形态辨认。** 表情语言、比例关系、动作习惯、声音与光粒表现可形成软识别线索，需在多种造型中验证。虚拟角色是否保留相同圆屏表达，是联合美术设计中的选择；实体屏幕仍须满足实际安装条件。

当前程序将种子眼、梨形身体和部分猫型装饰写为固定锚点。后续先完成新规范与存档兼容，再调整这些约束，保持当前形态与职业版本的唯一读取。

## 现有 STL 的适用范围

用户提供七个现有外壳与底座文件：

- `ESP-VoCat Lid.stl` 和 `ESP-VoCat main body.stl`。
- `echoear catbase ball.stl`、`echoear catbase cover.stl`。
- `echoear catbase platform btm.stl`、`echoear catbase platform top.stl`。
- `EchoEar catbase.stl`。

这些文件可用于识别分件、局部安装特征、开孔和外形。STL 未携带可独立确认的单位，各文件也有不同导出坐标；包围盒不等于整机装配尺寸。当前文件不能独立证明电子件包络、内部净空、机械行程、公差或可打印性。

原始 STL 在用户本地素材目录，不作为第一阶段文档的自动提交内容。CAD 阶段先确认尺度、坐标和装配关系，结合内部部件资料与样机测量建立基准。

## 最小核心的设计选择

| 需要比较的方案 | 比较内容 | 当前结论 |
| --- | --- | --- |
| 保护载体与主题外壳的分界 | 电子件由谁定位承载，换壳需拆哪些部件 | 待结构草模与装配比较 |
| 头部与静止底座的分件 | 主题件是否随头旋转，跨界配件怎样保持净空 | 待全运动包络验证 |
| 外壳的安装连接 | 定位、承力、反复拆装、打印误差和维护 | 不预设磁吸、卡扣或螺钉为最终方案 |
| 屏幕与声学窗口 | 装饰能改变哪些区域，接口怎样隐藏而仍可用 | 待样件功能对比 |
| 共用核心的尺寸与外观 | 保护与维修需求，主题轮廓所需空间 | 最小化以功能和装配成立为前提 |

核心标准化应减少主题外壳对内部装配的重复要求。外壳改变重量、重心、运动空间或磁性布局时，仍须验证对应功能。虚拟形态与物理壳各自保存版本，不自动映射成已安装状态。

## 测量与实验清单

| 项目 | 记录内容 | 进入下一步的条件 |
| --- | --- | --- |
| 电子件与安装 | 主板、屏幕、电池、扬声器、连接器、线束包络及固定方式 | 尺寸、来源、测量方法和装配基准明确 |
| 旋转与线缆 | 归位、实测运动范围、符号、线缆状态与头身净空 | 完整运动下无结构冲突，命令与实机方向对应 |
| 声学与触摸 | 裸机或原壳基线、新壳开孔、识别与触摸效果 | 同条件比较能发现变化，有实际记录 |
| 磁识别 | 壳签名、布局、装拆与不同姿态的识别结果 | 可区分已登记壳、未识别与未连接 |
| 重量与运行 | 原壳和主题件的质量、重心、转头与持续运行表现 | 在实际结构与电机上验证，不从模型图推断 |
| 制造与装配 | 打印机、工艺、材料、方向、壁厚、间隙、支撑和后处理 | 校准件与实际样件提供依据，未测数值保持待定 |
| 维护 | 接口可达、装拆顺序、连接与重复安装记录 | 换装和维护过程可重复完成 |

最终材料、壁厚、装配余量、负载和温升条件在样件实验后确定。历史草案中的建议值不能直接作为当前核心壳参数。

## 造型与制作工作流

1. 从实际生活提炼角色设计依据，写清愿望、投入、表达与辨认线索。
2. 根据实测包络与接口制作多种轮廓方案和结构草模，评审风格及功能冲突。
3. 完成可编辑模型与分件，说明连接、开孔、旋转、装配和维护方式。
4. 用指定工艺检查打印和后处理，制作校准件及低成本装配样件。
5. 在样机上验证屏幕、触摸、声学、接口、磁识别与完整转头过程。
6. 根据实际反馈修改结构和美术，保存模型、壳版本及校准记录。
7. 通过功能与制造验证后，再扩大主题变化或生成范围。

图像用于角色探索，可编辑模型用于几何与结构设计，打印样件用于装配和功能验证。各类产物分别验收，避免把视觉通过当作制造完成。

## 与软件和美术的连接

愿望与阶段读取共同经历，形成语义设计依据；造型版本引用当前阶段；实体壳拥有独立编号、结构版本和识别校准。安装事件只有经过识别才能更新实体壳状态，不反向宣布虚拟试做完成。

活动的虚拟动作、屏幕表情、声音和单轴注意回应分别设计。厨师方向可以提供信息与交流上的帮助，现实样机不具备实际操作厨具的机构。表达特色应与可执行能力一致。

当前软件边界以[身体协议](../protocol/body-perception-v1.md)和[固件审计](../hardware/body-bridge-audit-v0.1.md)为准。[历史外壳草案](../shell-interface-v1.md)保留为参考，其中 NFC、额外轴和未测数值不承担当前制造依据。
