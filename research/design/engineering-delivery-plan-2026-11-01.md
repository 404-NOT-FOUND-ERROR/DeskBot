# 聚形域工程状态与后续交付管线

2026-11-01。承接唯一产品基线 [开发架构、路线与原则](../../documentation/development-baseline.md)。本文将后续工作拆成可验收的交付批次；不替换既有世界、发展账本或已冻结实验，也不将计划计为完成。

## 结论与目标

当前是**可执行世界 + 已接入认知的研究原型**。已有时间、天气输入、有限资源、任务、私人记忆、社交约定和发展链；尚未证明每个 agent 能长期、有差异地持续生活。R3-A 仍是当前门槛，不能因自动测试通过就跳到量产角色外壳。

目标保持为同一个桌边个体喵呜：多源输入经过来源、时效、可知范围与作用权限分级，影响其处境和选择；行动真实耗时、耗材并留下后果。它能记住未完的事，也能改办法、求助、休息和放下。兴趣来自实际机会中的自主选择；持续兴趣、能力与试做使其提出“想成为谁”，再影响形态、职业与表达。稳定身份、变化节奏和清楚的信息表达须分别验证。

奇幻性需要可探索、可比较、有代价与后续的地方规律。扩大地图应扩大生活可能；森林、湿地、星屑台地的外形不能替代对应机制。实体仍遵守屏幕、双麦开孔、声学、触摸、磁识壳、单轴转头及装配约束；当前猫形不是永久造型限制。

## 按标准工程栈审视

继续使用模块化单体和受控工作进程，不为“标准化”拆出多套数据库或微服务。

| 层 | 当前栈与职责 | 需要收口的工程项 |
| --- | --- | --- |
| 领域核心 | Node.js 24、ES modules；唯一世界规则和原子提交 | 将庞大的生活协调模块逐步拆为明确的校验、执行、投影；禁止自由文本决定物理效果 |
| 认知适配 | Python 3.11+、固定 Asamana vendor、stdio 协议；Node 代理提供者 | 继续补完整 context/proposal 的版本合同；升级矩阵与错误码同源；保持 vendor 原文件可核验 |
| 数据 | SQLite WAL、命名空间、结果根、快照与历史压缩 | 显式 schema 迁移/备份恢复门槛；量测增速；区分原文与可重建索引，避免无期限复制快照 |
| 表现 | React 19、TypeScript、Three.js、Vite；同一读模型 | 业务位置与渲染坐标解耦；完成状态、昼夜与地区规律可见；增加关键用户旅程的浏览器回归 |
| 合同 | 共享 JSON 定义、Node/Python 验证与反例；当前 15 模块/16 接口登记 | 登记文件不是完整 Schema，也不是覆盖率；新增机制须复用约束与证据，避免各层重新猜语义 |
| 测试与 CI | 同一 `npm test`：架构、Python、Node、语音、前端、类型和构建；Windows CI | 继续增加接缝/恢复/内容迁移测试，冻结真实行为评测；不把提示字符串测试当端到端验收 |
| 运行与发布 | live/lab、预算预留、调用账本、失败层级和观测已有基础 | 正式启用开关、控制权交接、发布/回退说明、冷启动和恢复演练、运行小时成本与性能预算 |

当前提供者调用及端到端窗口延迟已有记录，但尚不能外推全镇全天费用或电脑功耗。先统计唤醒原因、无变化调用率、token、排队/模型/落库延迟、CPU/GPU 与每角色小时存储增长，再按测量优化。基础任务和环境变化不需要每个角色每秒调用模型。

## 按依赖推进的交付批次

每一批采用“问题与反例 → 合同/状态归属 → 实现 → 免费回归 → 必要的真实实验 → 发布记录”。先定义门槛，再运行；不中途换分母或把旧版本成功片段拼成新版本通过。

### A1 本轮：公共事件证据

已实现结果通知/摘录、送达回执、按条款限定的责任依据。选项、绑定正文、收件回执和后续事实依据共用同一记录。新协议采用前由 Node 再验，Python 同合同预检；不依据模型自我声明建立责任。见 [本轮交付](../milestones/r3a-event-evidence-2026-11-01.md)。

A1 时位置仅有本次亲见；A2 已补历史亲见、实际告知和时效衰减。旧消息无结构化回执时保持历史语义，不补造当时所知。

### A2 已实现并离线验证：目标身份、完成标准与复查生命周期

交付见 [A2 目标连续性](../milestones/a2-goal-lifecycle-2026-11-01.md)，接口见 [目标与位置规范](../../documentation/cognitive-goal-lifecycle.md)。下列出口已有离线证据；模型行为质量进入 A3 单独验收，不能据此声称长期生活已经通过。

- 保留目标稳定 ID，将 `completion_criteria`、本次方法/用途、已得证据、下一复查时间分开。现有 `goal_bindings`/followup 适配新结构，不能另建一套平行目标。
- 同目标可以换方法；相同方法的不同条件不能混作同一证据。“发出指定字段”核对接收者、结果根和字段；“了解规律”不能由一次动作自动结案。
- 规定新增、继续、改计划、暂缓、恢复、明确放下、证据满足的状态转换。等待到复查点不是行动失败；约定截止与个人复查时钟分开。
- 位置证据增加亲见/实际告知/历史位置的来源与年龄；没有位置依据也可以探索，但不能当作已知事实。

出口：原批目标反例、跨方法正例、跨夜等待、重复近义目标、历史目标迁移和 SQLite 恢复全部离线通过；无虚假完成、无无声改 ID、无“到复查点便失败”。保留开放愿望，不用相似文本自动合并不同目标。

### A3 下一批：R3-A 冻结行为验收

在 A2 完成后冻结新的源码、合同、内容、模型设置和上下文。仍用原四例、各五窗口；不续跑旧失败窗口凑数。至少 16/20 个有效且无关键事实错误，修复调用、失败与未运行窗口完整报告。按原停止规则保留现场；实际结果已完成但反馈失败时，只恢复反馈。

离线通过才发起有限真实调用；关键事实错误立即停止，不自动多抽几轮寻找成功。该门槛仅证明有限行为闭环，不能代替多人/自然跨日或美术验收。

### B R3-B 三个个体的双向生活

让喵呜与两位居民真正各自安排和回应，不能把静态接收者的不回复当拒绝。覆盖邀请、接受、拒绝、延期、离开、材料不足、共同任务以及对同一事件不同的私人理解。检查需要与个人事务是否被合作挤占。

出口：约定由真实双方选择，实际交接/共同成果可追溯；不读他人私人记忆、不重复催问、不重复付费或执行。先固定成对场景，再短时间实际调度；记录每人的机会、决策、等待、饥饿/疲劳、材料、成本与响应延迟。角色数量不能作为通过指标。

### C R3-C 地区包与新生活机制

选择 SandBox 中成熟的一处地区迁移意象、地形或渲染经验，先核验当时版本和许可。一个包同时提交地点/通路、地方规律、可作用物件、活动方法、资源循环、后续条件、人物机会、发展主题与表现绑定。

优先补现有选择缺少的机制，例如观察收集与比较、创作/烹饪变体、交换与协作、休闲和地方性公共事件；从少量相互作用的机制提炼接口，而非堆砌几十个活动名。每项要有投入、时间、成功/受阻/中断和可见后果。外围视觉地形可先保留为造景，不虚构已开放玩法。

出口：新旧存档迁移/回退、资源守恒、地理可达、人物脚底与物件表现、重启结算通过；在相同资源和需要条件下能产生有意义的不同选择，并比较输入影响。不能每加活动都改认知、记忆、兴趣核心分支。大型地图扩建在包接口经两类不同机制验证后推进。

### D R3-D 正式接线与运行预算

配置与秘密本机保存；明确旧规划器/新认知的单角色控制权、暂停/恢复、模型不可用行为和付费范围。统一健康、来源新鲜度、失败原因、待反馈与成本观察，保留聊天入口。先备份并在独立目录恢复，再验证升级与回退。

出口：关闭网页、断网、重启、待反馈、磁盘空间不足及重复回包均有明确行为；不丢事实或重做动作。以测量确定可接受的后台功耗、启动/恢复时间、上下文大小、延迟和存储增长，不先写未经测量的“达标”数值。公网部署与账户权限不在当前本地产品交付范围。

### E R4 自然跨日与发展节奏

先运行短时观察，再扩至数日。界面提供“为什么这样安排、哪些事尚未完成、什么实际改变了、哪些输入被采用/未采用”。不能要求用户自己阅读数据库来观察生活。

预登记指标包括：真实自主回访、不同可行机会中的选择、未完事项推进/放下、无新依据的重复联系、目标停滞时长、兴趣反复切换、愿望发生/撤回、需要公平性、输入配对差异和用户感知的生活连续性。注意/情绪、活动、兴趣和角色采用分层设节奏；允许合理安静，不用忙碌率做单一目标。

出口：用自然记录校准频繁变化与长期不变两端问题；公开失败与安静区间。只有兴趣与愿望的发生依据、节奏和持续性达到预定门槛，才进入具体角色资产的大规模制作。

### F R5/R6 表达、美术与实体

继续 low poly/NPR 统一材质、比例、轮廓和地域颜色。角色设计以已验证的兴趣/愿望与物理约束为输入：识别锚点、表情语法、口癖与声音风格、能力信息完整性、可组合主题配件分别设计。

先确认最小核心壳、旋转净空、麦克风与扬声器开口、屏幕可视范围、触摸与磁识别，再生成外挂壳概念；逐项经过 CAD、打印、装配与实机检查。小智/喵伴固件改造单独版本化，实体只输出其真实具备的能力。虚拟可以变成青蛙或厨师，不意味着实体可以跳跃、行走或凭空执行家务。

## Definition of Done

一批交付必须同时列出：范围及非目标、合同版本、唯一状态归属、兼容/迁移策略、成功与失败路径、幂等/恢复证据、自动门禁结果、必要的浏览器/模型/设备证据、剩余限制及可回退提交。未实施、已实现、离线通过、真实模型通过、正式运行、自然观察通过分开标记。

仓库提交包含源码、公共虚构实验报告和文档；不包含密钥、正式聊天、人生数据库、音频、依赖、模型缓存或下载副本。GitHub 是代码恢复来源，不能替代本机人生存档备份。
