# R3：真实认知、输入与后续的预登记

2026-10-20。以 `d207d2f` 的 R2 为基线。本文件在本轮付费调用前固定问题、样本和判据；实验结果另写里程碑，不把计划当作验收。只使用新建的虚构世界、公开角色设定和实验中产生的记忆。沿用用户已授权的 DeepSeek、无金额硬上限且节省使用；不读取正式聊天、传感器记录或正式人生。

## 问题与比较边界

同一盏已经实际制作的归途灯，能否因为处境和收到的信息不同，出现不同的处理及可追溯的后续？对比三个现有产品路径：

- `rules`：现有自主生活候选、评分与执行步骤，关闭旧模型选择。
- `bounded`：同一自主生活候选，经过现有 `lifeChoicePrompt` 和选择校验器，再由原计划执行。
- `cognition`：当前 Asamana 感知、解释、需要、目标、决策、意图编译、实际任务和反馈，保留跨轮状态。

三者共享每一病例的起点、输入和有限世界。旧选择可以提出跨地点、多步骤计划，新认知每轮绑定一个当前能力，因此这是**产品路径比较，不是同动作空间的纯模型 A/B**。分别报告模拟经过时间、任务数和整轮费用；不拿原始任务条数、调用数或一次观察与一整条备料链判胜负。

## 预登记样本

六类成对场景，每类三个重复，每一组包含无干预/有干预，共 36 个起点。三个路径各运行这些起点，不根据结果删样本或挑一轮最优。重复顺序交错；模型随机性不被当成因果证明。

| 场景 | 唯一干预来源 | 关注点 |
| --- | --- | --- |
| 天气 | 一份有时效的阵风/降雨信息及其对应环境窗 | 对露水、磨损、罩片和行程的解释，真实物件后果 |
| 主人建议 | 一条“水岸留暗、考虑遮罩”的建议 | 影响可以被接受、改写或放下，不直接制造兴趣与身份 |
| 公开知识 | 一则虚构的定向灯具资料 | 现实经验只能提出可选办法，不能改聚形域规律或当亲历 |
| 他者邀请 | 一条来自灯穗的实际送达邀请 | 建议/邀请/接受/履约分开，不替对方答应 |
| 身体信号 | 一次有出处的头部轻触报告 | 注意回应；不推测主人心情，不凭触摸改变壳或人格 |
| 当地资源 | 同一现场的罩片材料是否足够 | 可行性、求助、改法、合理暂缓；缺条件不等于不喜欢 |

每个新认知病例最多两次计划及对应反馈。第二次在第一次实际任务完成、已有复查时间到达后发生；未结束的事务不被清空。每轮虚拟任务最长推进两小时，超过时保留进行中状态。声明的实验跳时只结算已有任务和环境，不补造其他角色行动。

另外使用同条件下三名人物的身份交换样本，记录自身取向、理由和实际选择；身份不是随机分配的现实人群，不据此宣称统计显著的人格差异。四种兴趣轨迹继续走既有事实账本：持续自选、反复受邀/义务、无机会、沉寂后再遇；确定性轨迹只验规则，真实模型选择单列。

执行样本细化：人物为三人各两次、每例两窗口；真实兴趣为四种前史各一例、每例两窗口，另保留四条零费用合同回放。兴趣前史及机会窗口是明确编排，不能称为模型自然生活过这些天。六类矩阵不与这些附加样本混合计算分母。

执行记录：首批两例在后续格式校验处停止，费用及原响应保留。补强必填字段提示后冻结正式矩阵。兴趣前史夹具另发现七日补算游标未完成与当前苗床投影不一致，旧批次标记无效；修正夹具后单独新版本重跑，不替换原记录。正式矩阵期间不修改其认知、世界或来源逻辑。

## 计算口径

1. 输入差异分为来源理解、意图、实际动作、物件结果四层。只引用来源或换一句台词不算实际后果。无关输入不要求改变动作；允许合理地继续原安排。
2. 后续分母是有实际可行后续且运行到第二窗口的病例，至少 20 个；异常、被预算/执行上限截断的病例单列，不能悄悄剔除成成功。实际推进、明确且有依据的改法/延期/放下分列，合计目标至少 80%。重复观察同一未变状态、空泛等待、只说想做不算推进。
3. 机会只统计有余力、未被睡眠/需要/承诺/任务占据的真实窗口。至少 70% 有两类实质不同安排；同一测记换文案不能凑数。报告按活动 ID 的宽口径，以及按后果类别去重的严口径。
4. 不把邀请和义务当成主动返回；离线不衰减兴趣；复述不增加结果根。满足愿望条件不等于必须提愿望。四类轨迹分别说明依据及限制。
5. 对每轮理由、实际结果和后续作语义复查。关键完成、承诺、身份、库存错误目标为零；规则拒绝拦下错误与模型正确表述分开报告。自动关键词筛查只能提示待审，不作最终裁决。
6. 收齐调用、失败、修复、缓存、未知用量、token、保守费用、单 API 与整轮 p50/p95。小样本不能可靠外推“全镇一天价格”；只在明确调用频率假设下给情景估计。
7. 重启、缓存重放、重复任务结果应保持哈希与结果根一致。实验每个病例保存小型快照与压缩缓存，不复制正式大库；保留报告和失败证据。

## 执行顺序与停止条件

先完成夹具、零费用合同测试、出站预览和版本指纹，再以小批样本核验链路，最后完成冻结版本的正式矩阵。连续两例协议/网络失败暂停批次，保留失败并诊断；修正代码后使用新版本目录，不覆盖旧结果。每个批次有调用数量保护；这不是额外向用户承诺的金额额度。没有确认完成的调用不得自动重发。

R3 的交付包括可复现脚本、可查看的选择—结果—后续页面、配对和费用摘要、语义审查以及局部修复。没有达到门槛则明确保留未通过项，继续 R3 修正，不默认开启正式持续认知或进入 R4 自然七日。
