# 聚形域世界内容规范

2026-10-07 · 设计基线 v1 · 内容描述与实际运行状态分别管理

地点、设施、活动、项目、居民和角色方向共同提供生活可能。扩展内容需要说明它带来了怎样的选择、后果和后续，并接到现有唯一世界状态。当前活动与目录校验器继续执行既有合同，本规范逐项转为后续开发要求。

## 六类内容

| 类型 | 必须定义 | 与其他内容的连接 |
| --- | --- | --- |
| 地点 | 稳定身份、环境、通路、访问条件、时间天气影响和场景布局 | 可接触设施、可出现机会、居民活动与旅行 |
| 设施与物件 | 类型、登记能力、状态、容量、材料来源、使用与维护条件 | 实际活动目标、资源存取和视觉变化 |
| 活动 | 机会来源、参与条件、选择、过程、耗时消耗、结果、后续与表现 | 参与者、设施、项目、共同经历和角色方向 |
| 项目 | 主人、目标、阶段或分支、协作者、等待与退出、成果使用 | 多个实际活动和跨日后续，完成后改变可用条件 |
| 居民 | 欲望、顾虑、习惯、主要事务、关系和不同选择 | 实际候选与项目，可相处、延期、拒绝和合作 |
| 角色方向 | 愿望含义、关联经历、具体实践、采用后的生活与表达 | 原愿望、试做、阶段版本、艺术方案与实体约束 |

雾灯镇是聚形域中的初始聚落。地点拓宽可以包含森林、水域、星空和更奇幻的空间，但每个可进入地点都需要服务可核验的归属、通路和时间条件。地图展示的道路、设施和不可进入区域要与这些条件一致。

## 活动内容卡

以下字段是人可评审的设计内容，不是当前运行时可以直接安装的配置格式。新增规则需要实际执行器、校验、存档迁移和表现接入。

| 字段 | 内容 | 验收问题 |
| --- | --- | --- |
| 身份与版本 | 稳定活动编号、名称、内容版本、所属主题 | 更新名称后旧经历还能追溯吗 |
| 机会 | 怎样发现，什么状态或来源触发，何时过期 | 当时确有这个机会吗 |
| 参与者与动机 | 主动、受邀、需要、履约等；谁发起，谁实际参与 | 做成和想继续是否分别记录 |
| 前提 | 地点、通路、权限、材料、设施、容量、天气、人物安排 | 不可执行时能说明具体原因吗 |
| 选择 | 有限做法、替代办法、等待、求助与退出 | 至少有一个有意义的决策或明确的执行理由吗 |
| 过程 | 实际步骤、耗时、消耗、工具、预留、暂停与恢复 | 能在中断和重启后正确续接吗 |
| 结果 | 库存、对象、任务、关系与项目的实际变化；失败分类 | 后果是否来自实际执行且没有重复计数 |
| 后续 | 复看、改善、重做、分享、合作或收束条件 | 昨天的结果如何影响后来的机会 |
| 表现 | 开始、进行、暂停、结束与现场痕迹 | 画面、表情、声音是否读取相同状态 |
| 发展依据 | 哪些结果可支持兴趣或能力，哪些仅是接触、义务或等待 | 观察、搬运和试吃是否被误算成制作能力 |

活动实例保存当时的动机、方案、条件与实际结果。内容卡改变不追写旧实例。模型提出的未登记活动先作为想法保留；登记并验证执行方式后才可产生实际候选。

## 现有照料活动的完整设计示例

`water-bed` 当前在苗圃的 `garden-bed` 执行，耗时 300 秒，使用 `seedling-rack` 中三份清水。路线、库存与苗床条件由现有程序核验，完成效果来自实际结算。

| 项目 | 当前实现 | 后续设计接入 |
| --- | --- | --- |
| 发现与理由 | 根据苗床湿度、居民偏好等产生候选 | 区分巡看发现、昨天复看、朋友邀请、主动继续 |
| 前提与过程 | 目标、耗时、材料、通路、预留与结算 | 给失败、等待和求助提供具体后续条件 |
| 做法 | 当前固定浇水配方 | 新做法单独登记，核验不同耗水、目标和后果，保留原配方 |
| 兴趣与能力 | 原共同结果及动机；登记主题为照料 | 对照不同苗况的实践和实际后续选择，避免把义务次数当成喜欢 |
| 表现 | 已有苗圃对象状态与部分任务动作 | 补取工具、浇水过程、收工具和湿润痕迹，分别标注实现状态 |
| 跨日后续 | 现有苗床随时间与环境变化 | 安排可选择的复看，保存实际前后对象状态和方法引用 |

浇水成功不保证第二天苗木健康，不直接证明喜欢湿地或应该成为青蛙。新角色愿望仍使用原方向和试做规则。

## 现有配方对照

当前登记了 18 项基础生活配方和 20 项居民项目配方。登记表示有执行规则，项目阶段、材料与状态仍可能限制当时可用性。

| 分组 | 现有活动编号 | 后续规范重点 |
| --- | --- | --- |
| 苗床照料 | `water-bed`、`drain-bed`、`tend-bed`、`harvest-bed`、`sow-bed` | 巡看、复看、不同苗况与持续照料后果 |
| 采集与留种 | `gather-light-fruit`、`collect-water`、`save-seeds` | 来源、采集条件、补给用途与返回分配 |
| 工坊制作 | `craft-tray`、`craft-frame-kit` | 用途、试用、反馈及返工，有限材料不凭空补充 |
| 设施修缮 | `repair-frame`、`repair-bench`、`repair-rack`、`repair-stove`、`stitch-canopy` | 故障发现、排期、求助、维护后实际变化 |
| 日常烹饪 | `cook-moss`、`cook-grove-stew` | 备料、烹饪、送饭；配方完成与质量评价分别定义 |
| 日常进食 | `share-meal` | 分配、排队、吃完和需要变化；不算烹饪能力 |
| 浮圃项目 | `seedbed-survey`、`seedbed-plant`、`seedbed-inspect`、`seedbed-accept` | 主人与协作者、等待、独立检查和验收 |
| 浮圃日常 | `seedbed-care`、`harvest-float-bed`、`sow-float-bed` | 建成后的持续用途、维护与不同实际苗况 |
| 小泵项目 | `pump-survey`、`pump-assemble`、`pump-install`、`pump-trial`、`pump-accept` | 实际装配、试用、反馈与原材料链路 |
| 小泵日常 | `pump-water`、`repair-pump` | 已验收设施的使用与维护，实际节约的时间 |
| 叶芽汤项目 | `soup-record-ratio`、`soup-cook-trial`、`soup-serve-trial`、`soup-taste-trial`、`soup-confirm-recipe` | 批次、时间窗口、参与角色与各自真实行为 |
| 叶芽汤日常 | `cook-leaf-soup` | 保存配方后的实际重做与生活用途 |

旅行、观察、休息、资源搬运与社交约定是其他既有执行方式，不混入上述配方数量。规范化时采用同样的内容卡，保留各自执行器和事务规则。任务的 `care`、`craft` 等现有分类不直接决定兴趣：当前烹饪配方虽然使用 `craft` 任务类型，发展主题仍为 `cook`。

现有主题识别部分依赖活动编号前缀与固定地点。后续增加显式主题、实践范围和设施能力登记，再通过版本迁移接入；不能只增加标签就让新地点自动获得实践或角色资格。

## 观察 搬运与社交

观察要注明目的、现场可用对象和取得的信息。等待空位可以有计时和位置，但不给研究兴趣。休闲观察可以形成主动关注，不能产生配方能力。比较苗况、观测星空等新增观察内容还需要可核验的信息来源与执行记录。

搬运保存真实数量、来源、目的地和交接。它可以支持约定、项目和相关兴趣，不能把送汤者算成做汤者。合作保留发起、回应、到场、实际分工和交接结果；关系更新引用原共同事件，不能由各人的重复讲述反复增长。

试吃反馈的结论范围由其实际规则决定。当前项目反馈不能直接推断真实味觉、现实厨艺或普遍作品质量。新反馈机制要给出可观察依据和有限解释。

## 项目和生活后续

项目是有跨日目标的一组活动，按实际条件进入下一阶段。可以分支、求助、延期、结束或留下待解决的问题。完成应产生可使用的对象、配方、信息或关系变化；项目文本中的目标不是已完成成果。

机会、意图、已接受约定、执行中任务和已结算结果分别保存。现有任务继续使用原状态；后续意图可处于等待条件、可考虑、已安排、完成、取消或过期。该意图结构尚待实现，每次实际行动仍进入原任务与共同结果。

相同活动可以继续使用，但后续必须能指出所关联的对象、结果或问题。没有变化时允许明确结束，不为了推进故事补造故障和成功。

## 地点与居民扩展

新增地点需要提供真实的旅行与访问条件、至少一项已实现的可参与内容、环境影响和场景表达。仅供背景或远景的区域可以先发布为不可进入，并明确显示。当前地图校验器对场景位置、类型和目录能力有有限枚举；拓宽空间先升级合同、执行与呈现，再安装新内容。

新增居民需要有可执行事务、至少一种有意义的不同选择、可发展的关系、休息与资源安排，以及可辨认的表现。作者欲望和初始关系属于设计，后续完成、失约和共同经历以实际存档为准。

第一轮深化已有十二名居民的实际差异和三个项目，再根据活动空间与运行容量增加人物。无需把每位居民固定成一种角色方向的触发器。

角色方向扩展需要同时配齐关注路径、多个实际情境、具体试做、采用后生活、形态与表达方案。星空和梦境当前只有预留方向，开放前先交付这些内容。

## 表现与实体表达

活动表现读取实际任务、结果和对象状态，不能靠动画自行增加材料或完成任务。最低表现包含地点、开始动作、进行节奏、结束或中断及一项可察觉的后果；细化时再增加工具、协作姿态、镜头和环境痕迹。

虚拟角色的走动和完整动作属于世界表达。现实屏幕、声音与单轴转头各有输出计划，不能把虚拟走跳转成实体运动命令。设备未连接、输出未确认和实际安装壳未知时，保留相应状态。

美术设计读取角色愿望、当前阶段和实际生活形成设计依据；外壳制作再核验[实体约束](physical-constraints-v1.md)。内容规范不承诺自动生成可装配模型。

## 内容安装与存档兼容

每类内容使用稳定编号和版本。作者内容描述可能性，运行状态保存实际发生；装饰、地点目录和模型描述不能声明库存、完成项目或角色采用。

安装新内容前核验引用、通路、执行器、资源、容量与表现覆盖。新增规则有测试和迁移记录；更改配方不改写历史材料消耗。准备移除仍被任务、关系或阶段引用的内容时，先保留兼容记录和恢复路径，不能删除旧人生。

初期保留已有活动实现，通过补内容元数据和统一读取逐步接入。复杂活动仍由专门执行器核验；可复用的配方、搬运、观察与约定由既有执行方式承担。各项规则和内容通过评审后才进入正式世界。

## 新内容交付检查

1. 给出新增的生活可能与具体案例。
2. 完成内容卡和引用，区分作者目标与运行状态。
3. 核验前提、实际结果、后续、动机和共同根。
4. 提供成功、条件受阻、取消、重启与重复读取的验证。
5. 交付相应的动作、设施变化和清楚的信息呈现。
6. 安装与恢复保留原身份、经历、任务和阶段。
