# A3.1：修复后续事实边界，补目标覆盖并测量调用成本

2026-11-01，依据 [A3 实验](../milestones/a3-behavior-validation-2026-11-01.md) 规划；以下尚未实施。先完成免费实现与反例，再另行冻结真实验收，不把新结果并入 `cb2e483aa2bf`。

## 1. 先统一后续的事实依据和未来意图

沿用现有 followup、稳定 issue ID、结果根、goal_bindings 和 SQLite 单一提交者。共享合同需明确三类字段：执行器提供的已知事实引用、人物选择的下一意图、人物尚未验证的设想。不能只锁定 reason，却让 question 或摘要成为不受约束的第二事实来源。

为常规后续提供可验证的意图引用（等待哪条回复、比较哪个实际记录、询问谁、重访什么、暂缓或放下），事实部分由实际引用生成。奇幻想法可以保留为未验证设想，不直接进入“已发生”的事实投影、完成标准或交付状态。提示文本不是校验器，不把禁用“已经”等关键词当作主方案，也不为每个字段追加一轮模型裁判。

明确区分“消息已发出”“物品已展示/放置/转交”“对方已接受”“共同任务已完成”；每种事实都需要对应执行证据。没有展示动作时，不能把展示说成已发生；未来若新增展示，应作为真实能力接入，而不是解释掉本反例。

出口：捕获的原始错误反馈被拒绝或保持在明确未验证的表达区，不能进入可依赖的后续事实；正确的询问、未获回复、拒绝、实际转交和研究假说不被误拒。Node/Python 同反例判断一致，真实工作进程、下一轮读回和 SQLite 重启均覆盖；失败后不重做已完成动作。

## 2. 同步证据类型与使用资格

位置线索、消息回执、实际任务结果、外来信息和主观设想保留不同类型，但使用同一个引用目录说明“是什么、可以用于哪里”。上下文显示一个有效位置或回执 ID，而另一个字段只说“未知”，会引发不必要修复；应明确是不存在、不可见、过期还是用途不兼容。

出口：对每种引用分别验证允许与不允许的用途；无需模型猜前缀、复制旧 ID 或重述全文。不能因此扩大他人隐私范围或把听闻提升为亲历。

## 3. 补目标形成与生命周期的真实覆盖

空目标队列允许存在，不强制每次产生新目标。需要分别测量：已有 followup 能否满足眼前安排、何种需要/机会促成明确短期目标、已有目标到期如何维护。原矩阵八窗全空只能证明协议没有报错，不能证明生命周期选择质量。

先加免费接缝案例：有未完目标时跨方法、暂缓过夜、恢复后保留 ID 和标准、实际结果后完成、明确放下以及开放研究不误结案。另登记少量专门的真实覆盖情境，与原四例二十窗口分别报告；预置目标验证的是维护，不能冒充自然形成。允许不新建，但若关键转换没有发生，必须报告“未覆盖”，不能给功能通过。

## 4. 按调用明细控制成本

本批 16 次目标空更新约占 24% 估算费用。先区分空队列进度维护和可能产生新目标的机会：无目标、无结果相关目标、无到期复查时，检查能否在规则层跳过维护；不能跳掉所有目标形成机会。压缩模型不可使用的字段、重复证据正文和与本阶段无关的完成标准，保留引用与依赖闭合。

出口：免费固定上下文对照给出各阶段字符量、调用数、证据保留和空更新比例；旧反例、合法新目标及跨日维护不退化。真实费用改善只能在新冻结采样后报告，不能把减少提示字符直接宣称成账户省费。

## 5. 重新冻结并验收

合同、唯一状态归属、兼容迁移、字段级正反例、工作进程和重启恢复先通过同一项目门禁。旧 A3 原始响应仍用旧合同严格回放，不按新规则改写旧结论。

新版本仍重跑原四例各五窗口：20 个完整、至少 16 个有效、没有关键事实偏差；专门目标覆盖另列分母和门槛。保留相同停止规则、修复和费用账，不自动重复抽样寻找成功。只有原矩阵与专门覆盖都达到各自门槛，才讨论放行 R3-B；地区扩展和人物美术继续按总管线推进。
