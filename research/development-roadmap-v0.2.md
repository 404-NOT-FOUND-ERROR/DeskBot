# 毕设整体开发路线图 `v0.2`

**更新日期：** 2026-09-09  
**规划窗口：** 2026-09 至 2027-06  
**当前控制性目标：** 先证明“同一个角色会因持续经历形成可解释、可感知的角色方向”，再把方向转译为屏幕、声音和可装配外壳。

本版以 `聚形域世界观设定_v2.1.md` 和 `聚形域-角色与世界决策记录_2026-09-09.md` 为产品决策依据；`development-roadmap-v0.1.md` 保留为历史计划，不再作为当前排期依据。

## 1. 当前判断

软件底座已经不是从零开始：DeskBot Service 已具有 SQLite 持久世界、事件幂等、evidence、真实时间、天气及三类预报、近期对话、LLM 编排、设备 outbox、WebSocket/音频合同、假设备和研究会话；Web 已能展示世界、事件、天气、连接器和研究状态。2026-09-09 的服务端回归为 `118/118`。

当前最大的缺口也不是“再接一个数据源”，而是两件事：

1. 用户能否在真实 DeepSeek 多轮对话中稳定认出喵呜，而不是只看到一个带设定词的通用助手；
2. 世界线、外部事件、天气、稳定偏好和设备事件如何经过可审计规则形成“角色方向候选”，而不是直接播报或被一句话改写。

因此当前阶段只押一条主线：

```text
真实角色表达验收
  -> 多源证据形成方向候选
  -> 关系记忆与阶段试行
  -> 统一表达意图（文字 / 屏幕 / TTS）
  -> 固件与真机闭环
  -> 角色语义到可装配外壳
  -> 纵向体验与论文证据
```

## 2. 已完成、部分完成与未完成

### 已完成并有自动证据

- canonical 聚形域小世界、事件日志、world revision、幂等与 SQLite 重启恢复；
- DeepSeek/OpenAI-compatible 适配层和 prompt provenance；
- 真实时间、和风当前天气、短临/小时/每日预报的缓存与明确刷新策略；
- 多源层级进入只读 prompt，上下文不会由 LLM 回复直接回写；
- 假设备、命令 outbox、ACK 幂等、WebSocket DBA1 音频协议；
- 喵呜第一角色阶段、猫型第一形态、canonical `character_profile`、旧身份迁移和 `miaowu-expression-seed-v1`；
- Web 研究/体验页第一版和输入、事件、NPC、天气的可视化编辑入口。

### 部分完成，尚不能宣布验收

- **角色表达：** 结构与自动测试已完成；最终代码之后的真实 DeepSeek 多轮样本尚未形成完整验收记录。正式 `4311` 进程若未重启，仍可能使用旧提示词。
- **多源输入：** 已接入并分层；尚未把来源、权重、时间衰减、冲突和重复事件稳定转成角色方向候选。
- **关系连续性：** 已有有限近期对话和稳定偏好门槛；尚无长期记忆准入、更正、遗忘和自然回调合同。
- **表达输出：** 已有文本回复、TTS profile、音频/设备命令合同；统一 `expression_intent` 尚未成为文字、屏幕和声音的共同真相源。
- **语音：** sidecar 合同和占位基线存在；sherpa-onnx/CosyVoice 仍需在目标电脑与真实音频硬件上测首包、RTF、打断和音色一致性。
- **固件：** 由独立 agent 推进；DeskBot 侧合同已存在，但真机 hello、录音、播放、表情和 ACK 尚未闭环验收。
- **外壳：** 研究和接口约束已有历史材料；角色方向到 `visual_semantics`、可制造参数和实体壳的可追溯映射尚未跑通。

## 3. 当前执行阶段

### P1：喵呜真实表达与仓库基线（现在，1-3 天）

**目标：** 让“喵呜和中性助手明显不同”成为可复测结果，并把当前软件纳入正式版本管理。

工作：

- 重启正式 `4311` 服务，确保加载 `miaowu-expression-seed-v1` 和新 canonical profile；
- 按 `miaowu-expression-acceptance-v0.1.md` 跑八类真实 DeepSeek 场景；
- 对失败场景只改行为规则，不继续堆背景故事；
- 建立本地 Git `main`、GitHub remote、首个基线 tag 和 CI；
- 把角色可见行为、接口/迁移影响和人工验收写进 PR。

**退出门槛 G1：** 自动测试全绿；八类真实样本三项判定全通过；页面显示名/当前角色阶段/外壳形态不再混写；仓库无密钥、数据库或临时文件。

### P2：多源输入到角色方向候选（3-7 天）

**目标：** 输入能改变角色未来选择方向，但不能直接遥控人格、世界或外壳。

工作：

- 冻结来源层：世界线、外部事实/新闻、天气与时间、用户稳定偏好、关系事件、设备/在场事件；
- 为每条证据记录 `source/layer/confidence/occurred_at/observed_at/provenance/decay`；
- 用确定性规则先形成少量方向维度，例如好奇/守序、亲近/独立、谨慎/冒险、克制/外放；
- 将单次观察、重复印象、稳定倾向和候选身份严格分开；
- 在 Web 中分别显示原始输入、被采纳证据、方向变化、未采纳原因和规则版本。

**退出门槛 G2：** 三组固定事件序列可重复回放；候选方向一致；每次变化都能追到 evidence ID 和规则版本；单次用户命令无法直接写入角色阶段。

### P3：关系连续性与角色阶段试行（1-2 周）

**目标：** 让共同生活真正积累，但所有记忆和变化都可更正、可解释。

工作：

- 建立长期记忆准入、引用、更正、遗忘、冲突和敏感信息边界；
- 增加方向候选的 `observing -> trying -> accepted/rejected/deferred` 状态机；
- 让喵呜在试行期自然表现倾向，不直接宣布“人格已升级”；
- 用户只能提供经历、反馈和选择方向，不能越过证据链写入新身份；
- 记录主动交流的触发原因、冷却和打扰成本。

**退出门槛 G3：** 同一关系事实能跨会话正确回调并可更正；未记录事实不被声称记得；阶段变更包含证据、试行期、决定和旧阶段档案。

### P4：跨媒介表达意图（1 周，可与固件后半段并行）

**目标：** 同一个角色判断同时驱动文字、屏幕和声音，避免三路随机表演。

工作：

- 定义版本化 `expression_intent.v1`，包含 `mode/intensity/pace/prosody/expression/interruptibility`；
- 文本层负责口癖、称呼、句式与信息组织；TTS 层负责音色、音高、语速、韵律和能量；
- 屏幕表情只消费同一意图，不自行再判断一次情绪；
- 将严肃事实/安全信息的收敛规则写入输出路由；
- 在假设备上形成可回放的文字、表情和音频占位证据。

**退出门槛 G4：** 六类表达意图可重复映射到三端；同一回复不会出现文字担忧、屏幕开心、声音兴奋等冲突；无设备时不会宣称动作已发生。

### P5：语音和 ESP-VoCat 真机闭环（1-3 周，依赖固件 agent）

**目标：** 用真实设备完成一次且仅一次的“说话 -> ASR -> 角色 -> TTS -> 播放/表情/ACK”。

工作：

- 先完成按键/触摸触发的短录音批处理链路，再评估持续流式 ASR；
- 在目标机比较 sherpa-onnx ASR 基线与 CosyVoice TTS 候选，不把 s1-mini 当作 TTS；
- 固件只采集和呈现，不持久化人格、世界、密钥或研究真相；
- 冻结 hello、capabilities、音频格式、表情 ID、命令 ID、ACK/error 和重连语义；
- 完成断网、重复命令、播放失败和恢复试验。

**退出门槛 G5：** 20 次语音输入均只进入一次正确角色会话；20 轮无双重播放；相同命令不产生重复副作用；延迟目标以目标机实测冻结。

### P6：角色方向到视觉语义与可装配外壳（4-8 周）

**目标：** 让角色变化在潮玩式外壳上有大体感，同时满足机械双盲需要的尺寸、装配和制造证据。

工作：

- 从 P2-P3 的方向数据导出三组有显著差异的 `visual_semantics`，不把口癖数量直接映射成造型；
- 冻结中性电子内核、固定功能面、接口、公差、质量、重心、声学和运动包络；
- 先做轮廓/比例/细节密度先导，再进入参数化建模、网格修复和打印；
- 每个壳记录角色阶段、语义来源、STL、材料、参数、质量、重心、装配时间和失败返工；
- NFC/壳 ID 只确认实体身份，不自行决定角色演化。

**退出门槛 G6：** 三组外壳共享同一内核和接口；均可打印、装拆和识别；角色-外壳盲测出现可辨识趋势；至少一个代表壳完成工程级声学、温升、装拆和稳定性验证。

### P7：纵向体验、研究冻结与论文（2026-12 至 2027-06）

**目标：** 回答“第 30 天为什么还会回来”，并把工业设计体验和机械量化证据收进同一条论证链。

工作：

- 运行短期纵向/日记研究，记录主动回来、角色可辨认、关系连续性、打扰、惊喜与厌烦；
- 完成三类实验：可解释演化、角色-外壳匹配、换壳/旧壳历史体验；
- 量化装配、质量/重心、声学、热、稳定性、延迟和命令可靠性；
- 冻结源码 commit、模型/provider、规则版本、固件、CAD/STL、BOM、打印参数和匿名数据；
- 2027 年只做实验、分析、论文、展示和阻断性修复。

**退出门槛 G7：** 完整旅程连续演示三次；研究任务和分析计划经导师确认；每条论文结论都能指向日志、实验、制造记录或明确限制。

## 4. GitHub 正式协作方式

GitHub 用来固定可复现版本和 agent 间接口，不用来保存运行数据或密钥。

- `main` 只接收通过 PR 的可运行基线；工作分支按 `feature/`、`fix/`、`research/`、`docs/` 命名。
- 每个 PR 必须说明用户可见变化、canonical state/迁移影响、测试、真实模型/页面验收和固件影响。
- 必须通过 `DeskBot service tests`；角色行为变更还需附 `miaowu-expression-acceptance-v0.1.md` 对应样本。
- 服务端拥有世界、角色和事件真相；固件仓库拥有设备驱动。双方只通过版本化 hello、event、command、audio 和 ACK 合同协作。
- release/tag 用于论文证据：至少保留软件基线、真机闭环、外壳实验和最终答辩四个冻结点。
- 禁止提交 `.env`、`llm_config.json`、SQLite、音频、模型缓存、`tmp/`、下载仓库和任何 API key。

当前工作区已经准备 `.gitignore`、CI 和 PR 模板，但尚未获得 GitHub 仓库 URL；绑定 `origin` 和首次推送必须在 URL 明确后进行。

## 5. 明确不做

- 当前不新增论文研究问题、不扩张为通用 Agent 平台；
- 不继续增加天气/新闻等输入源，直到 P2 的采纳和归因机制通过；
- 不做摄像头、人脸识别、复杂运动、原生移动 App、社区或商城；
- 不同时维护 RisuAI/SillyTavern 产品分支，它们只保留为机制参考或实验对照；
- 不在 ESP32 上运行长期记忆、角色演化或完整 LLM；
- 不在角色方向和机械接口冻结前批量生成最终外壳；
- 不把自动测试、提示词存在或一次好看的回复冒充长期生命感证据。

## 6. 最近的验收顺序

1. 用户在保留 DeepSeek 与和风配置的 PowerShell 中重启正式 `4311`；
2. 按八类真实场景完成 P1 记录，并只修失败项；
3. 初始化/绑定 GitHub 仓库，提交 `software-baseline`；
4. 只实现 P2 的角色方向候选和可视化，不新增输入源；
5. 与固件 agent 对齐真机 hello、音频、表情和 ACK 版本；
6. P2 通过后才进入长期记忆、阶段试行和外壳语义。

路线图复盘点：P1 真实样本完成后立即复盘一次；P2 三组回放通过后再决定 P3/P4 并行程度。
