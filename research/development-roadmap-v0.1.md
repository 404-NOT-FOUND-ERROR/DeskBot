# 毕设整体开发路线图 `v0.1`

**制定日期：** 2026-08-14  
**规划窗口：** 2026-08 至 2027-06  
**适用范围：** 角色软件、角色状态研究、ESP-CLAW/VoCat 具身终端、可替换外壳、用户实验与论文交付。

> **2026-09-02 当前设定切换**：本路线图中的“铸造场”产品称呼属于早期规划用语；当前持续世界唯一事实源为 `聚形域世界观设定_v2.1.md`（v2.1），运行时 canonical 身份为 `shaping-001`。技术目录名 `foundry-web` 为兼容路径，不代表当前叙事设定。

## 1. 路线图结论

本阶段只维护一条主线：

```text
DeskBot Service（自研研究核心）
  - DeskBot Chat / LLM Gateway
  - 角色卡、世界条件触发与 prompt 编排
  - evidence ledger
  - role-state.v1 / revision / 双层阈值
  - ASR/TTS、设备 outbox
  - shell registry 与实验日志
          |                         |
          v                         v
聚形域 Web App                 ESP-CLAW Lua 适配器
  - 地图/事件/档案               - HTTP 命令与事件
  - 权重/候选/打印                - 音频/表情/base yaw
  - 旧壳历史                      - NFC/设备状态
                                      |
                                      v
                         ESP-VoCat v1.2 固定电子内核
                                      |
                                      v
                         中性内骨架 + 可替换打印外壳
```

开源项目的定位必须固定：

| 项目 | 当前决策 | 承担范围 | 明确不承担 |
|---|---|---|---|
| RisuAI | **机制参考与可选对照** | 情绪识别、情绪立绘、角色卡和对话交互参考 | 最终状态真相、CAPS 权重、硬件控制 |
| SillyTavern | **机制参考与可选对照** | World Info 的关键词、条件触发和选择性注入参考 | 最终状态真相、CAPS 权重、硬件控制 |
| ESP-CLAW | **主线设备运行时** | VoCat 板级初始化、Lua 硬件模块、HTTP/WebSocket、设备执行 | 角色身份和论文权威记忆 |
| ESP-VoCat v1.2 | **条件通过的电子基底** | 麦克风、扬声器、圆屏、网络、IMU、I2C、底座通信 | 中性内骨架、NFC、真正 head yaw、换壳接口 |
| DeskBot Service | **自研核心** | 可追溯状态、事件、桥接、日志、壳注册 | 大而全的商业后台 |
| 聚形域 Web App | **自研最小产品界面** | 旅程图中的地图、事件、档案、候选、STL 与旧壳 | 完整社区、商城或原生移动 App |

控制性目标是：**2026 年底前得到一个可记录、可打印、可装配、可进行用户实验的完整闭环；2027 年不再扩张平台功能，而是完成实验、分析、工作流文档和论文。**

## 2. 已知约束与规划假设

- 由一名工业设计学生主导，嵌入式焊接和大型软件维护不是研究贡献。
- 大模型、ASR、TTS 可运行在电脑、云端或第三方 API；ESP32 只做可靠执行端。
- ESP-VoCat v1.2 已组装到手；按目前刷机信息应为 Coze 固件，只作为硬件 bring-up 基线，具体版本以串口日志确认，尚未证明适合承担 DeskBot 主线。
- 开题报告计划在 2026 年底完成主要实验，2027 年进入论文和答辩阶段；具体校内节点以导师通知为准。
- 首轮使用自研 DeskBot Chat/API 作为主入口；RisuAI 与 SillyTavern 只做机制对照，不成为最终系统的必经运行时。
- 软件从一个模块化的 Node.js/TypeScript 服务开始，使用 SQLite 保存状态和日志；不建立微服务集群。
- 用户实验样本量、量表和伦理/隐私流程必须与导师确认，路线图不提前虚构正式样本量。

## 4. 推荐代码边界

```text
software/
  packages/
    protocol/              # JSON Schema、事件/命令类型、测试夹具
  services/
    deskbot-service/       # 状态、日志、ASR/TTS、设备 outbox、shell registry
  apps/
    foundry-web/           # 聚形域、事件、角色/旧壳档案、STL（技术路径保留）
  adapters/
    risuai-plugin/         # 可选情绪机制对照适配器
    sillytavern-extension/ # 可选 World Info 机制对照适配器
    fake-device/           # 无硬件联调器
    esp-claw-lua/          # VoCat 设备命令和事件接口
  fixtures/
    characters/            # 角色卡、静态世界书、固定对话脚本
    experiments/           # 输入序列、预期状态和回放数据

hardware/
  measurements/            # 实物尺寸和包络
  neutral-carrier/         # 中性内骨架
  shell-interface/         # 固定接口与校准件
  shells/                  # 角色外壳版本与打印清单
```

两个开源适配器都不进入主运行链；只有对照实验需要时才实现，禁止把它们扩成第二套产品 UI。

## 5. 阶段路线图

### Phase 0：架构与采购冻结（2026-08-14 至 08-23）

**阶段目标：** 决定现在要验证什么，并把不可逆采购和接口假设降到最低。

主要工作：

- 冻结 `interaction-contract.v0.1`、`role-state.v1` 和第一版角色/设备/外壳 ID 规则。
- 建立一个 Character Card V3、一个静态世界书和 10 条固定中文对话。
- 建立一个 DeskBot 角色卡、静态世界规则和 10 条固定中文对话；开源客户端只保存对照配置。
- 向卖家确认 ESP-VoCat v1.2 完整成品、主板丝印、自定义刷机能力和旋转底座配置。
- 记录当前 Coze 固件版本、分区、完整 flash/NVS/SD 备份和可回滚方式；不要把 Launchpad 外部 OpenAI `0.2.3` 镜像当作主线候选。
- 建立开源清单：commit、版本、许可证、修改范围和恢复固件。

**退出门槛 G0：**

- DeskBot 主线、RisuAI/SillyTavern 机制对照和 ESP-CLAW 设备运行时的权责不再含糊。
- 角色卡、世界书和固定对话可以导入、备份和恢复。
- 已到手的 VoCat v1.2 能完成基线开机、Wi-Fi、触摸、录音和播放测试，并且原始固件可以回滚。

### Phase 1：无硬件软件闭环（2026-08-24 至 09-13）

**阶段目标：** 在碰真实硬件前证明“对话 -> 可追溯状态 -> 具身命令”成立。

主要工作：

- 创建 `deskbot-service`：`health`、`/api/chat`、`/api/event`、CAPS-inspired 短时状态、evidence、LLM 编排、设备 hello/outbox；再替换为 SQLite 日志。
- 把 `role-state-v1.schema.json` 生成 TypeScript 类型，所有提交先校验再持久化。
- 创建网页假设备：显示表情、模拟语音、yaw 控件、命令确认和故障注入。
- 建立 DeskBot Chat/LLM Gateway：输入事件 -> 条件触发 -> CAPS 临时状态 -> prompt -> 回复 -> 输出计划。
- 参考 RisuAI 的“文本情绪 -> 状态 -> 立绘”机制，建立可解释的情绪分类与表情映射。
- 参考 SillyTavern World Info，建立关键词、时间、事件和传感条件触发的情境注入。
- 用 `fake-device` 完成 `device.hello`、命令轮询、执行日志和 ACK 幂等，真实 VoCat 只在下一阶段接入。
- TTS 先放在 service/bridge，输出 `audio_ref` 给假设备，并保持唯一出声路径。

**退出门槛 G1：**

- 连续 30 轮中，每个输入和最终回复只记录一次；reroll、重试和流式输出可去重。
- 每轮使用的 `role_revision` 可追溯，重试时状态 marker 始终只有一个。
- LLM、TTS 或设备离线时分别产生结构化错误；已接收事件不丢失，恢复后可重放。
- 假设备对相同 `command_id` 只执行一次。
- SQLite 迁移前，明确标记当前内存服务不能通过重启持久化；持久化退出门槛移到 G1.1。

**开源客户端边界：** RisuAI 与 SillyTavern 都不是最终系统依赖；它们只用于核对机制、导入格式或形成实验对照。

### Phase 2：VoCat 与 ESP-CLAW 实机闭环（2026-09-14 至 10-04）

**阶段目标：** 把假设备替换为真实电子内核，但暂不做角色造型。

主要工作：

- 验证 VoCat 屏幕、双麦、扬声器、电池、USB、IMU、I2C 和磁吸接口。
- 在 `esp_vocat_board_v1_2` 上构建/烧录 ESP-CLAW，并保存可恢复固件；当前 Coze 工厂固件保留为 A/B 硬件基线。
- 首轮不用改 C 核心：以 Lua HTTP app 提供 `/api/lua/foundry/...` 的 `hello`、`command`、`events`、`record` 接口。
- 用现有 Lua `display`、`audio`、`image`、`uart/i2c` 模块执行表情、音频和底座命令。
- 输入语音先采用可控的批处理链路：

```text
设备触摸/按钮
  -> 录制短 AAC/WAV
  -> bridge 下载文件
  -> 电脑/云端 ASR
  -> conversation.input
  -> DeskBot /api/chat
```

- 只有批处理语音无法满足旅程和延迟要求时，才评估自定义 C/WebSocket 音频流。
- TTS 主线仍为 PC/云端生成音频并由设备播放，避免电脑与桌宠双重出声。
- Launchpad 的 `speaker_openai_0_2_3_ctm_esp_vocat_1_2` 不进入主线：它是外部托管的旧 Realtime/WebRTC 镜像，不能替代 DeskBot，也不能假定仍兼容当前 OpenAI API。

**退出门槛 G2：**

- 原机连续运行 30 分钟，重启、断网和恢复流程可重复。
- `speak`、`render.expression`、`orient` 各执行至少 100 次，无重复命令副作用。
- 20 次设备语音输入均恰好一次进入正确的 DeskBot 角色会话。
- 20 轮对话无双重播放；屏幕反馈 P95 目标小于 1 秒，语音开始 P95 目标小于 2.5 秒，目标值在 E0 实测后冻结。
- base yaw 必须记录为 `orientation.base_yaw`，不得伪装为 `head_yaw`。

### Phase 3：多源角色演化与聚形域最小界面（2026-09-21 至 10-25，可与 Phase 2 后半段并行）

**阶段目标：** 证明角色变化来自可解释证据，而不是最近一句提示词。

主要工作：

- 将输入分成世界级和个人级，定义来源、权重、时间衰减、冲突和重复事件降权规则。
- 冻结稳定层、变化层、语义距离门槛和叙事合理性门槛。
- 建立三组可回放事件脚本，对应至少三种不同角色方向。
- 聚形域 Web App 只实现研究所需页面：
  - 当前角色与 evidence；
  - 世界事件与个人事件；
  - 候选身份/外壳理由；
  - 历史 revision 和旧壳档案占位。
- DeskBot 保存静态角色语义和世界规则；动态 role-state 每轮临时注入 LLM，不回写静态角色卡。

**退出门槛 G3：**

- 同一事件序列重复运行时，状态方向和候选结论一致；所有偏差有随机性或人工修正记录。
- 每次身份变化能追溯到 evidence ID、规则版本、前值和后值。
- 三组角色变化能分别生成合法 `visual_semantics` 和 `embodied_response`。
- 用户能从界面回答“为什么它发生了变化”，但看不到不应暴露的模型内部推理。

### Phase 4：中性内核、NFC 与工程壳（2026-10-05 至 11-15）

**阶段目标：** 电子功能与角色外壳彻底解耦。

主要工作：

- 拆机审计并测量 CoreBoard/BaseBoard/MicBoard、屏幕、双麦、扬声器、电池、天线、接口和底座基准。
- 第一版优先保留屏幕/双麦前框和底部技术基座，先替换侧面与背面；完整中性载体放在验证后。
- 设计固定功能面、主控模块、声学/电源卡匣和底部接口模块。
- 接入 I2C NFC，建立 `shell_id`、标签 UID、打印版本和角色归属校验。
- 打印无造型工程壳与间隙校准件，冻结 `shell-interface.v1` 的尺寸、公差、质量、重心和运动包络。

**退出门槛 G4：**

- 工程壳完成 10 次无损装拆，换壳时不触碰 PCB、FPC 和电池胶。
- 原壳与工程壳完成声学 A/B；唤醒/录音能力下降不得超过预先冻结门槛。
- 最大计划质量和重心下完成 50 次左右转动，无倾倒、碰撞、断电和 UART 丢包。
- NFC 20 次识别无重复安装事件，错误 `shell_id` 不会提交角色状态。
- 封闭运行 30 分钟无不可接受温升、Wi-Fi 下降或音频反馈。

### Phase 5：角色语义到三组实体外壳（2026-10-26 至 12-06）

**阶段目标：** 证明同一内核能承载可辨识的角色身份跳变。

主要工作：

- 从三组事件脚本得到三组结构化角色概念和 `visual_semantics`。
- 先做低成本轮廓/比例/细节密度先导实验，再锁定三种方向。
- 形成可记录的形态流程：概念生成 -> 几何生成/建模 -> 参数化接口 -> 网格修复 -> 打印清单。
- LoRA 只在通用模型无法稳定保持角色视觉语言时启用；不把训练 LoRA 当作必须交付。
- Grasshopper/Blender 等工程处理必须记录人工干预、参数和失败案例，不能把半自动流程描述为全自动。
- 每个外壳输出 STL、`shell_id`、接口版本、打印参数、质量/重心、NFC 绑定和语义说明。

**退出门槛 G5：**

- 至少三组外壳使用同一电子内核、接口、材料和主要打印参数。
- 三组都能完成打印、安装、拆卸、NFC 确认和旧壳归档。
- 盲测先导实验能够区分角色—外壳匹配趋势；正式阈值在 E1 后预注册。
- 任一失败件都有失败类型、返工原因、材料/时间和版本记录。

### Phase 6：完整旅程、先导实验与范围冻结（2026-11-16 至 12-31）

**阶段目标：** 用一个完整场景验证“角色连续性 + 身份跳变 + 用户见证”。

完整演示脚本：

```text
初始回廊漫游者
  -> 日常 DeskBot 对话与世界/个人事件
  -> evidence 与 role_revision 累积
  -> 角色请求打印构造组记录者外壳
  -> App 展示理由和 STL
  -> 用户打印并安装
  -> NFC 检测与服务确认
  -> 表情、朝向和语音回应
  -> 旧壳进入实体与 App 档案
```

实验准备：

- E0 工程可行性：延迟、稳定、声学、旋转、NFC、装配。
- E1 语义先导：轮廓/比例/表面语言与角色匹配。
- E2 可解释演化：有/无 evidence 链对变化合理性的影响。
- E3 实体体验：跨媒介一致性、安装仪式、旧壳历史和情感依恋。
- 统一匿名化 DeskBot 聊天、服务日志和访谈数据；如使用开源客户端对照，再单独记录其导出数据和删除流程。

**退出门槛 G6：**

- 完整旅程连续演示三次，无人工改数据库或临时改代码。
- 先导参与者可以完成对话、查看理由、安装、确认和查看旧壳历史。
- 根据先导结果冻结正式任务、量表、样本量方法、访谈提纲和数据分析计划。
- 2026-12-31 后不新增客户端、传感器、运动自由度或社区功能。

### Phase 7：正式研究、分析与论文（2027-01 至 03）

主要工作：

- 完成导师确认的正式实验和必要的短期纵向/日记研究。
- 分析可解释性、跨媒介一致性、角色—外壳匹配、装配数据和情感依恋结果。
- 整理完整工作流：输入、权重、状态、生成、工程处理、装配、换壳和评价。
- 形成限制说明：开源依赖、外部 API、样本、短期实验、base yaw 与 head yaw 差异。
- 冻结可复现包：源码 commit、插件、服务、Schema、固件、CAD、STL、BOM、打印参数、匿名化数据和日志模板。

### Phase 8：论文定稿与答辩（2027-04 至 06）

- 只处理论文、图表、展板、演示可靠性和答辩问题。
- 保留一个离线/录屏演示方案，避免答辩依赖现场 API 和网络。
- 除阻断性故障外，不更新 DeskBot、ESP-CLAW、模型 provider 或硬件版本；开源客户端只冻结用于对照的 commit。

## 6. 测试总表

| 测试层 | 必须回答的问题 | 关键证据 |
|---|---|---|
| DeskBot Chat/LLM | 能否稳定完成状态注入、生成回复并产出设备输出 | 30 轮事件日志、重复提交、离线恢复 |
| 角色状态 | 多源输入是否可解释、可复现、可审计 | evidence、revision、规则版本、三组回放脚本 |
| 设备协议 | 命令是否幂等、可确认、可恢复 | command ID、ack/error、P95 延迟、重启测试 |
| 语音链路 | VoCat 音频能否经外部 ASR/DeskBot/TTS 返回设备 | 20 轮录音、ASR、回复、播放日志 |
| 表情与动作 | 小屏和朝向是否表达同一角色状态 | 表情命令、base yaw 记录、视频编码 |
| 中性内核 | 换壳是否不触碰电子件且保持功能 | 10 次装拆、声学/无线/热测试 |
| 外壳系统 | 三组语义是否可辨识且均可制造 | 盲测、打印/返工、质量、装配时间 |
| 换壳仪式 | NFC、角色回应和旧壳档案是否形成连续体验 | 安装事件链、访谈和历史档案 |
| 研究复现 | 他人能否按文档重做核心流程 | 版本锁、脚本、Schema、CAD、BOM、日志 |

## 7. 明确不做

以下内容不属于当前阶段目标：

- 同时开发 DeskBot 主线和两套开源客户端产品插件。
- 为了性能改用 VoCat-S31、自焊 Ditto 或自研主板。
- 在 ESP32 上运行完整大模型、角色长期记忆或演化规则。
- 摄像头、人脸识别、四足行走、复杂机械臂或多自由度动作。
- 在角色状态、假设备和工程壳通过前开发精美 App、社区、商城或原生移动端。
- 在 E1 先导结果前训练 LoRA 或批量打印最终外壳。
- 把 RisuAI/SillyTavern 的 Memory 当成论文 evidence ledger。
- 用模型不可见的内部推理作为用户可解释性证据。

## 8. 风险与降级路线

| 风险 | 预防 | 降级路线 |
|---|---|---|
| 可选对照客户端版本/API 变化 | 仅在正式对照实验时冻结版本、适配器 hash 和测试脚本 | 取消该对照，不影响 DeskBot 主线 |
| DeskBot Web 与本地服务的 CORS/代理问题 | 首轮同源托管并做 contract smoke test | 由服务自带最小输入页 |
| 硬件实时语音过难 | 先做短录音文件 + 外部 ASR | 用户按键/触摸触发；答辩用固定录音或 PC 麦克风 |
| 外部 TTS 延迟或格式不兼容 | TTS 统一由 DeskBot Service/bridge 调用并转码 | 设备播放预生成音频 |
| 原猫壳不能完整拆为内核 | 分阶段保留屏幕/双麦前框 | 第一版只更换侧背壳，论文如实记录约束 |
| 底座负载不足 | 先冻结质量、半径和重心上限 | 固定底座或降低壳体尺度，不增加复杂运动 |
| NFC 受磁铁/扬声器干扰 | 提前做位置和距离试验 | NFC 移到固定接口环；实验阶段保留手动确认备份 |
| 三组外壳无法按期完成 | 先做工程壳与三组局部语义样件 | 保留三组完整外观，但只对代表壳做最高精度表面处理 |
| 用户实验时间不足 | 10 月完成招募和先导设计 | 缩小功能范围，不缩减核心对照与制造数据 |
| 数据分散和隐私风险 | 统一匿名 ID、备份和清理策略 | 只保留研究所需字段，关闭不必要的云同步 |

## 9. 现在决定与下一步验证

**现在决定：**

- DeskBot Chat 是唯一主运行入口；RisuAI 与 SillyTavern 只进入机制对照，不并行维护产品级客户端。
- 角色状态、外壳状态和论文日志由独立 DeskBot Service 管理。
- ESP-CLAW 先以 Lua HTTP app 适配，C 固件改动是后备方案。
- LLM、ASR、TTS 放在电脑/云端/API；VoCat 只做具身执行。
- 聚形域和外壳档案做独立最小 Web App，不重做 RisuAI 核心界面。

**接下来验证：**

1. 一周内完成 G0：记录已到手 VoCat v1.2 的固件、分区、备份和硬件基线。
2. 三周内完成 DeskBot Chat + DeskBot Service + 假设备的 G1；开源客户端适配器另行排期。
3. 完成 G1 后再做 G2 和工程壳；当前 Coze 固件只用于基线，不开始刷旧 OpenAI 主线或角色造型。
4. G1-G4 全部通过后，才批准三组最终外壳和正式用户实验。

## 10. 毕设完成定义

毕设不是以“代码功能很多”完成，而是以下成果同时成立：

- 一套可复用、可解释的多源输入到角色状态工作流。
- 一套可替换的 DeskBot LLM/TTS 适配器和独立角色状态/设备协议。
- 一个能够展示地图、证据、身份候选、STL 和旧壳历史的软件系统。
- 一个经过验证的 VoCat 固定电子内核和通用外壳接口。
- 至少三组由不同角色概念驱动、共享同一内核的可打印外壳。
- 完整的打印、装配、拆卸、NFC 和设备反馈测试记录。
- 一套用户实验、数据分析、限制说明和可复现研究资料。
