# 喵呜与居民共用的自主生活循环

2026-10-04，第五步。版本 `morrowmere-autonomous-life-v1`。主角与当前三名居民使用同一套“需要与兴趣 → 可行目标 → 分步执行 → 实际反馈 → 重新安排”的循环，计划、需要、冷却和反馈保存在原有 canonical world 的 `autonomy` 中。

## 当前可体验的生活

喵呜偏向照料、制作和探索；巡路人偏向探索与修缮；拾影者偏向照料和光色观察；传声员偏向水岸行程和做饭。人物 ID、名字、位置、关系和共同经历继续沿用已有存档。十二名作者居民的安装、改名及人物迁移在第六步完成。

本阶段决策策略为 `bounded_rules_v1`：依据当前需要、设施状态、固定兴趣与带日期的确定性选择决定优先级。它能自行安排并留下后果，但还没有模型参与高层目标选择，也没有从反馈中学习新人格。反馈目前用于失败后的重新安排及冷却；跨事件的理解、记忆沉淀和缓慢成长在第八步建设。现有聊天仍使用原有模型配置。

| 情境 | 自发安排 | 真正改变的状态 |
| --- | --- | --- |
| 23:00—06:00 或精神低 | 回住处休息；无路则就地休息 | 真实休息时恢复精神，环境继续推进 |
| 食欲升高 | 确认长桌餐食；必要时取苔芽、做饭、存餐，再吃饭 | 消耗真实食材与餐食，吃完才降低食欲 |
| 苗床失水、积水或衰弱 | 浇水、疏通排水、整理苗床 | 消耗有限清水，核验并改变苗况 |
| 苔芽成熟或苗床空下 | 收获、重新播种 | 苔芽进随身袋，苗床清空或消耗种子 |
| 设施磨损 | 备料、制作修补包、出行、修缮 | 消耗材料、留下真实产物及设施恢复 |
| 喵呜想做东西 | 制作育苗托盘，带到育苗架存放 | 木料与紧固件减少，随身袋及育苗架托盘增加 |
| 暂无紧迫事务 | 到有兴趣的地方待一会儿，或休息 | 持久出行与活动记录；观察活动不产生资源 |

精神和食欲为角色生活状态，范围 0—1；初次安装为 0.78 和 0.35。精神平时每真实小时减少 0.025，实际运行的休息任务每小时增加 0.22；食欲每小时增加 0.025。完成旅行、制作和一般活动还有有限精神消耗，吃完一份饭降低食欲 0.65。暂停休息停止恢复。它们不是现实身体的生理测量。

## 执行及边界

每个计划由旅行、取放、配方活动、休息或观察构成。候选阶段使用一次性副本检查路径和材料链；副本中的位置、材料和结果不会写入存档。实际执行每一步时重新核验当前位置、路径、库存、空间权限、设施条件和其他居民的预留。每位角色同一时刻只有一个进行中或暂停中的任务，共用设施执行互斥。

任务使用第二步的真实耗时和第四步的固定配方；取放也经过同一个资源验证器。每一步在事务副本上成功后才提交，避免任务容量等错误造成部分扣料。材料短缺、道路封闭或完成时条件变化会产生明确反馈；角色等冷却后重新安排，不远程修理、不瞬移、不凭计划生成产物。

服务每分钟最多为八名角色各推进一个计划步骤；目前四名角色全部覆盖，顺序轮换。一个成功目标通常冷却两小时；失败目标二十分钟，失败后最早一分钟重新决定；用户取消后留三十分钟再决定。冷却针对目标，不阻止其他合法选择。现有约定与管理行程的角色预留优先，已有作者日程不再与自主循环重复安排行动。

服务持续运行时，关闭网页不影响安排。停机后只补算已经开始的任务与真实经过时间；没有执行的新计划从恢复当下开始，不补写停机期间的出行或对话。分钟事件、任务结果、计划步骤和反馈持久化，重启及同一事件重试不重复扣料或完成。

初始补给有限。无有效降雨补充时，清水可能用尽；食材、材料和种子也可能不足。此时记录不可行的候选，选择其他活动，不自动补满仓库。居民交换、协作和补给来源继续在第六步建设；本阶段不宣称具备完整封闭经济。

## 观察和控制

- `GET /api/life/autonomy`：只读策略、四名角色的需要、计划、反馈、库存及最近生活记录。
- `GET /api/world/map`：附带同一份自主生活读模型、真实任务和对象状态，读取不推进生活。
- `POST /api/life/autonomy`：仅接受主角的 `pause` / `resume` 与可选 `event_id`；其他角色 ID、能量、目标或资源字段不参与写入。同一 ID 重试复用发生时间并去重。
- `POST /api/event`：仍拒绝公开 canonical mutation，不能伪造生活状态。

3D 客户端与研究界面显示自己的安排、理由、精神、食欲、居民当前实际任务和最近反馈。当前任务优先于作者场景叙述。点击“暂缓自发安排”只停止喵呜下一次安排，已经开始的任务仍继续；当前任务另有暂停、继续和取消按钮。恢复后继续原计划或重新判断。

开发服务提供 `/life-review.html`，读取独立三天规则回放的七个截面。回放使用相同世界、资源、任务和自主循环，每五分钟采样，包含一次重建；不注入历史天气，也不读写真实 SQLite。画面读取实际回放对象状态，因此托盘、库存、苗体和空苗床继承第四步的模型变化。生成脚本为 `apps/jev-town-client/scripts/build-life-review.mjs`。
