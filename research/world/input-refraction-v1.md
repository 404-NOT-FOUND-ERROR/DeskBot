# 现实输入参考 v1

第七步在同一个持久世界中安装 `deskbot.input-refraction.v1`。安装不创造过去的输入；网页读接口不开始行动。它提供来源、观测时间、有效期、意义、建议、采纳或暂缓理由以及原始任务引用。

## 接入口与权限

| 来源 | 当前接入 | 可影响的内容 |
| --- | --- | --- |
| 上海天气 | 既有 Open-Meteo 服务端连接器 | 有效雨雪或强风降低露天兴趣候选，允许去室内歇一会儿；水位、苗床湿润仍由已有环境引擎结算一次 |
| 用户 | 对话与 `POST /api/life/inputs` | 六种有限建议：浇水、照料、托盘、水边、林间、休息。其他说法保留为用户提供的信息，不能建立世界事实 |
| 身体 | 已绑定喵呜的设备协议 | `sensor.touch` 的 head/screen；`sensor.microphone_direction.angle_degrees` 的 -180 至 180 度；`shell.install.detected.shell_id` 的标识。保存感受，不猜身份、视野，不改变人格 |
| 外部消息 | 服务端 `refractionSources` 与 `ingestRefractionSource` | 保留配置的来源名称、链接与观测时间；仅配置适配器给出的白名单 `topic_code` 可形成有限建议。当前生产未配置新闻源 |
| 其他 agent | 同一服务端登记机制，kind=agent | 信息或提议通过同一行动校验；当前生产未配置 agent 源 |
| 世界 | 已有实际任务与资源事务 | 输入参考被采纳后引用 `plan_id` 和 `source_task_ids`，只有实际任务链完成才能记为完成；地图、设施、关系事实继续由其领域事务拥有 |
| 模型回复、ASR 阶段、回执 | 审计 | 不进入生活候选，不成为独立成长证据 |

服务器确认参数独立于消息内容。公开 `/api/event` 不能通过 `source_kind`、`provider`、置信度或 provenance 冒充服务端来源。未绑定设备上报也不获得喵呜的身体感受权限。协议上报并不证明真实硬件已联通；物理设备联调留在第九步。

## 如何影响选择

建议等到下一次正常空闲选择；不会抢占运行或用户暂停的任务，不强制恢复自主安排。候选分值有限且同主题不叠加。饥饿、严重疲劳、苗床积水、已有约定和材料或路径前提继续有效。浇水建议在苗床不缺水时暂缓。目标完成沿用两小时冷却，失败沿用既有重规划规则。

目前采用明确的规则与有限中文匹配，不使用模型作高层目标判断。否定、引述和不支持的句子不作为动作建议。复杂对话仍须第八步接入受约束理解和目标判断，不能把这一版本称为完整自然语言理解。

输入遵守合同有效期（设备 5 分钟、用户与外部消息 24 小时、天气使用连接器实际到期时间），重复原始出处只考虑一次。参考过期后不参与新的选择；已开始的任务仍按原先规则继续。存档上限为 96 条参考、384 个去重键、64 条近期记录，保留正在执行的参考，避免长期堆积。所有参考的 `independent_evidence` 为 false；第八步须依据实际经历另外建设成长证据。

## 界面和独立验收

侧栏的“现实带来的小事”可发送生活建议，看到先记下、暂缓、已纳入安排、完成或失败。记录视图保留来源信息，明确用户提供信息与亲历结果的区别；没有配置的源显示实际状态。

`/life-review.html?sample=inputs` 为七个独立固定时钟切片，涵盖建议送达、采纳、照料完成、先休息、不重复浇水、模拟雨天和模拟设备。其他居民暂停自发安排；这些是专项样本，不能当作正式生活历史。生成命令为 `node scripts/build-input-review.mjs`，不读取生产 SQLite、不请求网络。
