## 为什么停止

第一例 `resources-1-off` 的模型选中了实际可执行的装罩选项，然而把 `self_actualization` 填入 `motivation`。这个值是 Asamana 的**需要类型**，不是 DeskBot 的**行动来源类别**。后者用于区分需要驱动、自主探索、延续旧事、他者邀请和已接受的义务，影响后续兴趣证据的归属。

原系统提示虽列了允许值，Python 绑定阶段没有集中检查；后置校验只提示“motivation、来源、标题和理由必须符合选择合同”。模型一次修复仍原样返回，最终以 `upstream_decision_failed` 停止。模型输出错误与接口诊断不充分共同造成这次失败。所选动作本身合法，不等于完整选择或生活闭环通过。

原理由还说装罩之后才能测记，当前执行器没有这个前提。这段被拒绝的文字没有制造世界事实，但它说明个人解释仍需单独审查。修正一个字段不能据此宣布自由叙述准确或人物生活有趣。

## 免费修复与接口归属

新增 [行动字段合同](../../contracts/cognitive-decision-fields.v1.json)。Python 提示、Python 绑定与 Node 采用共用六个行动来源值和错误码；需要状态仍保留 Asamana 原有表达，不改 vendor，不取消需要驱动。

`共享字段合同 → 模型选择 → Python 精确校验 / 一次原有修复 → Node 因果证据复核 → 原世界任务`

- 当前目录选择和旧单次选择都在绑定前检查该字段。诊断明确字段、收到的值、允许值及两套概念的区别。
- 没有把 `self_actualization` 自动改写成 `need` 或 `self_continuation`。若需要修复，由模型明确重新选择；原响应保持不变。
- 终止错误带 `cognitive_motivation_invalid`，归入合同层，保留失败阶段；不写成角色经历，不增加重试次数。
- Node 保留既有因果证据核验。合法标签本身不能授予自主兴趣、旧事延续或约定资格。
- 旧批次仍保留原错误码和失败判定；新诊断只属于修复后的版本。未来冻结版本已登记新的共享文件。

修复后的认知相关源码版本为 `7f8337331a6a`（按同一 runner 的 5 窗口哈希计算，尚未真实复验）。接口登记现为 12 个模块、12 个接口。完整 context/proposal/followup 仍不是一份全面共享 Schema；本轮统一了已被真实反例证明存在问题的字段边界。
