# R3-A 单次选择、确定性执行与有限复验

2026-10-25。承接 [整体管线](../design/r3-to-r6-execution-plan-2026-10-21.md)和 [本轮预登记](../design/r3a-single-choice-2026-10-25.md)。本轮工程、有限实验和记录整理完成；**R3-A 的生活质量门槛仍未通过，未放行 R3-B 或正式持续认知。**

## 当前实现

`Asamana 个人需要/人格/记忆 → 一次结构化选择 → Python 确定性绑定 → Node 原有校验与实际执行 → 事实、个人感受和同一事项的后续`。

新增 `single-choice-v1`：角色明确选择方法、用途、事项、收件人和表达。程序绑定这些选择，不再调用另一个模型重复编译活动/问题编号。活动、耗时、材料、库存、联系冷却、来源权限和结果仍由原世界执行器负责。

- `current` 引用本人当前事项，`selected_activity` 引用本人选定活动；缺少方法不从文字猜测。
- 本人明确复查已完成一步时，程序读取该事项的原目标和已存在证据；收束仍区分客观完成、个人满足和放下。
- 实验用途绑定同一问题和一批产量；备用有限，自用/交付必须有已知用途或已接受条款。不因某用途缺失而发明消费者。
- 收件人从可见名单映射到当前可联系名单；非法或重复编号整条拒绝。Node 核对绑定回执，禁止在绑定后换掉方法。
- 新路径去掉决策与编译之间的重复上下文，保留个人需要、经历、关系、身体约束和出处。旧冻结合同继续可读。
- JSON 模式在出站前要求明确 JSON 指令；不合法请求不占费、不出网。失败终止事件可被严格回放，不自动重试接口。

上海天气本机配置已恢复为 Open-Meteo，公开科学信息、空气和预报状态按实际调度/时效展示；启动默认不做付费 LLM 探测，显式 `-ProbeLlm` 才探测。正式旧调度仍在原设置下运行，新的连续认知未启用。

## 实验与真实结果

计划仍为原 `resources-1-off/on`、`invitation-3-off/on` 四例，每例五窗口。沿用虚构起点和模拟时间；不包含正式聊天、传感器或人生存档。先跑材料对照，有最终错误即停。其他居民本轮不运行自主回复。

| 冻结版本 | 实际范围 | 模型请求 | 结果 |
| --- | --- | ---: | --- |
| `17fb2d6ecfb4` | 材料充足例第一轮 | 3 | 决策请求未明示 JSON，HTTP 400；0 完整窗口、0 已执行行动。保留失败，旧终止缓存不完整，未宣称严格回放通过 |
| `c71847ce58c4` | 材料充足五轮，材料短缺第一轮 | 39 | 5 个完整窗口 / 6 个进入窗口 / 20 个计划窗口。缺材料例初答和唯一修复都把正文放在 contact 内，最终拒绝；整批停止，邀请两例未运行 |

第一次格式失败后曾明确修订预登记，只允许一次格式修正版，并把新批上限减为 167 次，连同旧三次仍不超过原 170 次。修正版停止后没有追加付费版本，没有换起点挑选结果。

材料充足例的实际顺序：邀请灯穗 → 借灯净滤四份水 → 首次询问苔团是否用得上 → 安装一片遮光罩 → 再次询问苔团。取水与装罩两步归入同一事项的完成历史；水没有凭留言转移，罩片实际消耗。只取水一次，没有继续囤积。

但不能把五次执行成功视作五次生活质量通过：

1. 六个决策窗口只有一个首答直接采用，五次用了唯一修复。除最终正文层级错误，还出现了遗漏活动 ID、遗漏收件人、复用已复查目标和遗漏观察对象。协议负担仍明显。
2. 第四轮完成装罩，记忆却把结算瞬间的取整数值理解为整段任务蓄光完全没少。期间实际蓄光约 0.796 → 0.789333；变化含自然耗光，不能直接归因于安装。
3. 第五轮有装罩的新结果，却又问同一批清水要不要。对方未回、清水和交付条款没有改变。当前事项范围过宽，灯的新结果不应自动成为再次询问水需求的理由。
4. 自由问句/意愿中夹带事实仍可能通过结构校验。原文确实送达，只能证明“说过”，不能自动证明“说的都对”。

作者逐条核对按本轮保守口径记 **3/6** 有效选择/推进；不是盲审。第 4 轮因记忆问题、第 5 轮因重复询问不计质量通过，失败轮保留在分母。样本数也未达到二十窗口。因此本轮不具备 R3-A 放行依据。

`c71847ce58c4` 严格缓存回放：两例初态/终态 **2/2 一致**、停止原因 **2/2 一致**、新增调用 **0**。包含原失败，回放一致不等于行为成功。

## 开销和延迟

本轮两批合计 **42 次请求**，提供商报告输入 **430,261 token**、输出 **5,654 token**。已知用量按项目登记单价估算 **¥0.61924904**；第一批 HTTP 400 未报告用量，保留预留 **¥0.113406**，合计上界 **¥0.73265504**。预留不是实际扣款，账户账单未知。只凭本批不能外推全镇日费用。

修正版 39 次请求中，5 个采用窗口的模型编译次数均为 0，但感知、动机、反馈、记忆和后续仍有模型调用。单次选择没有把持续认知简化成每轮一次 API。

逐阶段、窗口延迟与全部费用保存在 [R3 回顾页](http://127.0.0.1:5173/r3-review.html)；此前版本与失败记录保留在历史折叠区。

## 接下来的收口顺序

仍在 R3-A 内推进，不用增加场景来遮盖当前缺陷：

1. **先收紧交流目的与新依据。** 将“灯怎样留暗”和“这批水是否需要”分别跟踪，同时保持同一生活事项。对相同接收者、同一批物品、相同数量/条款，未回复且条件未变时不重复询问。其他目标的新结果不能自动刷新资格；实际回复、需求变化或明确不同条款才是新的依据。
2. **事实表达与个人感受分别验收。** 更多结果用可读的证据片段表达；数值包含时间区间、精度与因果边界。感受可犹疑，不能因包在“我的感受/打算”中就绕过事实约束。不靠不断扩充正则声称能裁决任意自然语言。
3. **继续降低首答合同错误。** 用本批全部失败输出做本地回归，核对动作类型与所需字段一致性。允许语义等价的序列化形式，仍拒绝缺失/冲突的真实选择；不由程序替角色选活动或收件人。
4. 上述本地反例先通过，再登记下一次小批实验；同一冻结版本至少二十窗口、至少 80% 有具体依据的推进/改法/延期/放下，同时报告首答采用率和全部失败。不合格不追加抽样刷成功率。

通过后进入 R3-B 的少量人物双向回应。R3-C 再按内容合同引入成熟地区、用途和事件机制；R3-D 接入正式生活；R4 做自然时间观察。地图与外壳设计不能替代这些出口条件。
