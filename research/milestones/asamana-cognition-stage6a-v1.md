# 6A 时间等待与后续衔接

2026-10-12 · 本地实现与固定隔离案例 · 第六阶段仍未整体完成

本轮修正模型上下文的时间表达、等待覆盖原问题、无条件重复送达消息，以及实际任务反馈后的事项引用。同期交付 [聚形域世界与风语林草案](../design/shaping-field-world-sketch-v1.md)；新区域尚未实现，地形、规则、人物往来和 3D 制作进入 6B。

## 实现

- `cognitive-continuation` 提供同一瞬间的 UTC、当地时间和时区；方法冷却由已有凝光苔、浮铃、夜灯规则计算，钟表到期与其他条件可用分别说明。
- Python 只在模型提示展示中标注 ISO 时间的本地/UTC 含义；实际存档和证据原文不改写。整秒时间用于表达，原认知步仍按世界实际经过的小时计算。
- 等待可绑定本人方法、本人已送达消息或本人约定。引用需在当次上下文中存在；不能等别人的私人消息。关联回复由实际收件、发件者和 `reply_to` 一起确认。
- `continue/postpone` 等待保留原问题、结果出处和首次等待时间。复查可按实际冷却到期；回复等待六个现实小时后进入重新考虑，改写理由不能续期。睡眠、运行任务和已接受的事务仍由原调度优先处理。
- 六小时回复复查参数与“六小时连续已观测自由窗口停滞”诊断不同；前者不代表兴趣衰减，不强迫完成或放弃。参数仍待自然生活调校。
- 已送达的相同内容尚无关联回复时，不重复执行送达；记作受阻尝试，由反馈考虑别的办法。实际回应或约定条款变化允许重新沟通。不同措辞的语义重复没有被证明全部识别。
- 任务反馈保留同一事项的稳定编号、最初依据和本次结果根；最近十六项衔接及明确放下/另起的旧事项保存为有界回顾。等待和文本整理不添加实践、材料或对方承诺。

## 规则回放

两个零提供者调用的回放走原有限执行器：

1. 刚测过浮铃 → 明确等待实际半小时 → 保留原问题 → 到期方法可复查 → 编排选择实际复测并留下新记录。
2. 实际消息已送达 → 复查两次仍无回应 → 等待起点不变 → 六小时回复复查边界 → 编排选择明确暂缓，保留原问题与经历。

回放的时间、供给、人物位置和选择由夹具编排，不代表模型自主成长或自然跨日。

## 少量真实模型复查

以第五阶段四个失败方向和一个正例为针对性案例，重放各例第一回合的实际选择/受阻尝试与生成后续，再进行一次新真实安排和反馈。没有重建旧模型全部目标、需要与隐含状态，不能当作严格随机 A/B 或总体成功率估计。

| 案例 | 本轮实际结果 | 仍存在的边界 |
| --- | --- | --- |
| 平静水岸 | 到期正式测记，正确区别 11:04 与 12:04 上海时间 | 仅验证这一次复查 |
| 广场夜灯 | 无回应时实际测记自己的余辉 | 新后续说“明早”，复查时间仍在同日夜间；复查与下一步执行需要继续区分，后续未验证 |
| 合片余辉 | 到期取第二个数据点，没有重复递送同一问题 | 新后续仍提等回应，能否之后合理收束待观察 |
| 苗圃缺水 | 实际前往回声水岸，沿找水问题改变方法 | 尚未实际取水、带回和补给，不能说缺水已解决 |
| 风起水岸 | 实际完成浮铃测记 | 反馈把新测记误称为“调整瞬间读数”，分类错误未消除 |

共五项实际任务完成，五份反馈通过形式采用；43 次提供者调用，用量均已知，按本轮沿用价格版本的保守估算约 **¥0.6085**。单例包含模型安排、实际任务结算和反馈，中位耗时约 **13.97 秒**、最大 **16.61 秒**，不等于单次 API 或日常聊天延迟。

模型实验记录版本为 `f36f09c2101f`。随后补充事项历史和已结束约定允许重新邀请的规则，不重新生成模型反馈；最终代码另作零费用回归。自由文本仍有错误，第六阶段质量出口尚未达成。
