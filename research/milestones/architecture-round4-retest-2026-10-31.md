## 根因与免费修复

原提示将同一份事项合同用于规划和反馈，包含“归档完成步骤、选择下一完成标准”等规划指令。反馈校验其实禁止这些动作，但修复提示同时要求步骤对象的正确字段。模型因而补全了一个在本阶段根本不应出现的对象。这是接口与提示的阶段归属不清，不能归结为提供者宕机。

同时发现 Node 的反馈接纳只对部分字段逐项检查，可能保留未识别的规划附带字段。仅改 Python 提示不足以保证世界边界。

新增 [共享反馈阶段合同](../../contracts/cognitive-followup-phases.v1.json)，接口登记为 12 个模块、13 个接口：

| 阶段 | 负责什么 | 不能做什么 |
| --- | --- | --- |
| 计划 | 本人选择行动、延续或恢复事项；凭实际证据归档步骤；行动前选择完成标准 | 把未执行意图记成成果 |
| 世界执行 | 核验、预留材料、实际耗时与结算，保存结果根 | 根据模型叙述凭空补效果 |
| 结果反馈 | 对实际结果形成记忆；保留、暂缓或有依据地收束当前事项；表达未来意向 | 新绑定目标、归档步骤、换成另一个事项或再次执行动作 |

- Python 提示、Python 校验和 Node 接纳使用同一反馈字段清单。反馈投影移除尚未绑定的目标选择与规划合同标记，保留当前目标、真实证据和已完成历史。
- 修复提示明确“删除越界字段，不要补全或填 null”，将归档留到下次计划。没有在生产代码中替模型删字段或改写意愿。
- 再次越界的错误为 `cognitive_followup_phase_invalid`，归入合同层并保留 `feedback/followup_repair`。其他错误仍报告其自身原因，不沿用上一次错误标签。
- 合法的继续、暂缓、满足后收束或主动放下仍保留。客观 `resolved` 仍要求原目标证据；没有把“步骤完成”强制变成“整个研究结束”。
- 继续沿用一次合同修复；没有第二个规划器、额外编译调用或无限重试。

修复后认知源码版本为 `5cade88ab56a`，**尚未真实模型复验**。原冻结记录仍保持 `semantic_contract_rejected_after_retry`，不以新诊断覆盖历史。

## 验证与证据

37 项针对性回归通过，包括真实 Python 子进程、Node 接纳、原世界执行器与三个连续窗口。修复后统一 `npm test`：**1,359 项通过**（架构 4、Python 84、Node 929、声音 16、前端 326），无失败或跳过；类型检查及生产构建通过。已有部分前端包超过 800 kB 的构建提示仍在，本轮没有改地图资产或拆包。

关键反例使用原 22 条响应，逐条验证哈希。新代码重放到第三窗口仍明确拒绝两次非法反馈；世界任务和消耗已经发生，待反馈控制权保留，新计划被阻止。随后另用**测试编写的纠正响应**补一次反馈：不重复任务、不再消耗罩片、只记录一次事实与经历；当前目标仍携带完成证据，下次计划才可归档。绕过 Python 直接将非法字段交给 Node 同样拒绝，不部分提交目标或记忆。这是离线恢复验证，不是模型自行修好。

修改核心代码前已完成原版本严格缓存回放，22 条响应全部命中、无网络回退、初末状态和停止原因完全一致。离线新代码回归与原版本严格回放分开计数，均不计入真实实验通过率。
