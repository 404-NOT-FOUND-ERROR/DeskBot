# R3-A 第三轮：当前选择、目标与后续共用机会

2026-10-28。承接 [开发基线](../../documentation/development-baseline.md) 的第三轮“回路统一”，使用第二轮已登记的方法、用途与条件证据。**第三轮实现与离线验收完成；真实模型连续生活仍需第四轮冻结复验。**

## 交付与架构

新增 [机会合同](../../contracts/cognitive-opportunities.v1.json) 和 [接入规范](../../documentation/cognitive-opportunities.md)。原选项目录集中核对有限用途、试验条件和联系回执，机会模块投影出可执行或有具体阻碍的机会；当前选择、短期目标、反馈后的下一步读取同一来源。

`方法与世界状态 → 具体用途与条件 → 本人机会 → 当前选择 / 短期目标 / 后续 → 世界任务与结算 → 事实证据与个人复查`

Node 仍是唯一世界裁决者，SQLite 仍通过原事务保存。Python 保留 Asamana 的需要、目标队列、决定、记忆与反馈，在 vendor 外用 `OpportunityNeedEngine` 替换已有的目标生成调用，不增加另一个行动规划器。接口登记增至 12 个模块、11 个接口；共享目录负责版本和引用边界，完整生活 Schema 仍待继续集中整理。

| 过去容易脱节的入口 | 本轮处理 |
| --- | --- |
| 当前库存够用，但后续又安排“再取一批” | 后续与当前选择使用同一有限用途；用途消失后进入复查，不能从活动名称恢复权限 |
| 将装罩冷却误当成使用冷却 | 每项机会携带实际方法的条件；已经可用不能声明等待，个人稍后再做仍被允许 |
| 对同一条件重复测记或借实验继续囤货 | 读取第二轮真实条件证据；已满足条件不再提供相同实验机会，普通观察仍可选择 |
| 改做别事后原问题丢失，或恢复时重开等待期限 | 保留事项 ID、条件身份和原等待起点；暂存问题到期也要求复查，迟到的真实回复可以唤起 |
| 相同用途未回复却换说法再联系 | 当前与未来联系均读取同一回执；实际回应保留证据，不因显示收件箱轮转丢失 |
| 模型把目标标成完成，却没有真实成果 | 明确绑定具体机会步骤；必须核对本人任务、结算、冻结观察及机会身份，结果根在任务轮转前保存 |

未来引用只表示打算，不预留材料或保证成功。短期目标可以保持未绑定设想，不从文字猜活动；绑定步骤完成也不等于研究完成、稳定兴趣形成或角色愿望实现。旧 `activity/social` 简写只在唯一对应具体用途时兼容，歧义引用保留原问题并要求复查。

## 仍未完成

- 新合同下真实模型能否持续选择、正确复查、合理休息和形成变化，尚无新真实实验结论。最近证据仍是计划 20 个窗口、进入 7 个、完成 6 个、严格有效 4 个的 [失败实验](cognition-r3a-catalogue-2026-10-25.md)。
- 有限选项目录的联系表达仍受控；开放对话、多人物私有理解、长期拒绝关系和新的奇幻机制分别需要后续开发与验收。
- 新增绑定步骤保留少量完成根；绑定条目、联系用途的长期归档、跨版本迁移和真实存储增长留待 R3-D。原热任务轮转和 SQLite 重启测试不能替代多年容量验证。
- 尚未迁移的旧活动、完整内容包合同与表现适配继续按 R3-C 推进。三种方法及其机会的一致性，不证明任意地区规律都已通用化。

## 下一轮：R3-A 第四轮冻结复验

1. 冻结源代码、合同、模型设置和隔离初态；预先登记固定 20 个窗口、顺序、最大调用数、停止条件和评价表。准备工作不调用模型，不读取正式聊天或传感器记录。
2. 在运行前验证出站上下文和提供者格式，检查共同反例。付费运行只使用这份冻结版本；故障不回退到规则答案，也不换病例重抽成功结果。
3. 逐窗口记录来源、原事项、可用机会、选择及动机、实际任务与资源变化、结果、个人记忆、下一步，以及调用/token/费用/延迟。合理休息、延期、换事和放下可算有效，不能以“必须做实验”奖励执行数量。
4. 判定至少 16 / 20 个有效窗口且无关键事实错误：库存、交付、答应、因果和完成证据不得伪造；语义有效性另做人工复核。失败保留原始结果，修复后使用新的版本记录，不改旧分数。
5. 通过后进入 R3-B 的少量人物双边生活；再用 R3-C 的新地区与相互作用机制检验扩展性。正式运行与自然多日观察分别在 R3-D、R4 验收，之后才细化角色、美术和实体工作流。

20 窗口是有限工程行为门槛，不能证明多源影响的统计因果、稳定兴趣、全镇自然生活或奇幻叙事质量。
