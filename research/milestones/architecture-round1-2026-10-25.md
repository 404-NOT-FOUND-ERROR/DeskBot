# R3-A 第一轮：开发基线、接口登记与失败诊断

基线建立于 2026-10-25，离线验证完成于 2026-10-26。承接用户确认的规范化开发路线。**第一轮工程交付完成；R3-A 的真实连续生活验收仍未通过。**

## 本轮交付

1. [开发架构、路线和原则](../../documentation/development-baseline.md) 成为当前统一基线。README、贡献指南和主要旧路线文档指向它；旧实验结论保持原样，避免把后来的代码修正记作旧实验成功。
2. [调用链与状态归属](../../documentation/interfaces.md) 对应 [可检查的接口登记](../../contracts/architecture.v1.json)：登记 10 个模块、9 个接口，区分作者定义、提案、命令、世界状态更新、唯一持久化提交和只读表现。检查真实文件、入口、版本、消费者及证据路径；这不是完整静态依赖分析，也不是全部生活合同已经共享化。
3. Node 与 Python 共同读取 `cognitive-failure.v1.json`。错误报告保留阶段、原始符号错误码、已知原因、人物和任务标识；区分传输、提供者、预算、合同、决策、状态过期、世界前置条件与未知原因。分类不改变重试政策，技术故障不写成人物经历。
4. 诊断接入真实 stdio 桥、认知协调器和持久化 job。修复取得 job 执行权后、组装上下文异常未进入失败处理的问题：现在会结算为失败，记录 `context` 阶段，避免停留在“调用中”。SQLite 重载能保留诊断，不新增生活记忆或任务。
5. 根目录 `npm test` 统一执行接口检查、Python 认知、Node 世界、语音边界、前端全部测试和生产构建。CI 改用同一入口，并显式配置 Python 与 Windows 时区数据，取消会漏掉认知改动的不完整路径过滤。GitHub 上的工作流尚未运行，本轮证据来自本机。
6. 新增源码指纹工具，纳入未提交的 Python、合同、文本代码与版本化内容，排除正式数据、密钥、运行缓存及二进制美术。生成的是哈希清单，不是源码或人生数据库的恢复备份；真实实验原有的冻结源码与响应证据继续保留。

## 下一轮的具体目标

进入 R3-A 第二轮“机制登记”，首先迁移普通汲水与借灯净滤这组已有失败案例，再用一个新机制验证接口可以扩展：

- 共同描述方法、用途、需要的条件、实际作用、可观测完成证据、兴趣主题与版本；由世界执行器作最终裁决。
- 区分普通生产与可验证实验。比较必须引用真实条件与结果；条件发生实质变化可以重试，改名或重新措辞不能变成新实验。
- 让认知选项从同一登记生成，保留安静、休息、换事和放下。新机制不能依赖在认知、记忆、兴趣各处增加活动名称特判。
- 先覆盖成功、资源不足、用途已满足、条件变化、重复、取消、过期和恢复反例；通过后再进入第三轮，把后续事项与短期目标接到同一机会合同。

完整 context/proposal/followup 共享合同、所有活动的机制化、多人物正式生活、地区可安装包及美术/实体工作都不属于本轮已完成项。第二、三轮完成后，第四轮才冻结同版本的 20 窗口真实实验；当前最近真实证据仍是 [进入 7 个、严格有效 4 个的失败实验](cognition-r3a-catalogue-2026-10-25.md)。
