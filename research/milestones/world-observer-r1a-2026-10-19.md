# R0→R1A：可恢复基线与同版本生活观察

2026-10-19，本地实现与验证。承接[整体 R0–R6 管线](../design/integrated-architecture-roadmap-2026-10-19.md)与[第一轮空间打磨](shaping-field-round1-2026-10-19.md)。这一批完成恢复检查、同版本当前观察和运行方式说明；R1 的完整历史、操作回放、存储治理及 live/lab 预算分离尚未完成。

## 本批目标与实现

过去正式入口分别请求地图、生活、角色，交互完成后还会把较早的动作响应混进较新的地图。现在 `/api/world/snapshot` 同步捕获一次 canonical world 与 mutation head，地图、人物、当前故事、近期生活记录、角色愿望/实际试做/采用阶段和运行诊断均由该版本生成。读接口不推进世界、不调用模型、不创建认知实验库。

角色投影函数新增可传入的 world/at；原调用方式兼容。观察路径把捕获的 world 一直传到愿望、试做、阶段预览，避免在内部又读到新世界。正式聊天、旅行、任务控制、NPC 互动和角色采用之后，界面统一重读完整快照，不再局部覆盖 map 或 life。

客户端用一份状态原子替换所有投影。世界版本、记录序号、进程标识和本次捕获序号共同阻止旧请求倒退；重启后的同等或更高记录可接受，较早恢复存档会明确提示重新核对。连接有 10 秒超时，失败时保留最后快照；15 秒轮询、网络恢复和切回页面会重读。聊天输入与本次快照独立，刷新不会清空草稿。

3D 场景完成这一版本的实际绘制提交后才回报“生活与画面已同步”；8 秒未确认显示等待，WebGL 不可用时明确显示文字视图状态。这是首帧提交确认，不代表人物已经走完路线或 GPU 测试。画面仍按真实任务进度表现行走与工作。

新增折叠的“生活运行与同步状态”：逐人显示规则生活、有限模型选择、已约定计划、连续认知、暂停或工作进程未启动；记录当前设施占用和多个未结束任务的冲突。归属是对既有调度规则的只读诊断，本批没有新建一套调度器。正式世界目前 13 人，**连续认知登记 0 人**；不把模型辅助选项称为已经完成持续自主认知。

身体连接、对话历史和跨日日记有独立生命周期，不伪称属于当前世界快照。NPC 认知输入也不会接收观察者全镇视图。天气接口仍可能返回过期参考，页面如实标注，不在本批伪造新天气。

## 分支吸收边界

参考累计实验节点 `1270533425215bc5aba6d24a3cf13a74dd0529df` 的 `world-observer`、`worldObserver.ts` 和 `renderCompletion` 合同，重写适配当前 main 的 Python 认知、试做/双轴阶段和新地图。没有整分支覆盖，没有引入其另一套认知 worker。

这次采用 HTTP 同版本快照；WebSocket、冻结历史分页、历史 render ACK 和完整操作回放仍在 R1 后续。未照搬实验分支的任务裁剪，因为当前客户端还依赖最近完成任务判断到达和失败。

## R0 本地恢复检查

- `scripts/checkpoint-local.py` 保存 tracked 与非忽略源码，额外排除本机密钥、依赖及数据；SQLite 使用在线 backup API，包含已提交 WAL，不直接复制运行中的数据库文件。
- 修改前保存 755 个源码文件并实际解压逐个比对 SHA-256；完整人生库通过 `PRAGMA integrity_check`，各 namespace 行数及 canonical payload hash 与清单一致。
- 完整 Git 历史与本机全部 refs 保存为 `history.bundle`，`git bundle verify` 通过。未提交的视觉/本批代码由源码包保存，不能只靠 bundle 恢复。
- 使用真实 `createPersistentWorld` 加载备份，持久化适配器只读，时间固定在存档时刻，不启动服务/模型。13 人、14 地点，人物、任务、库存、记忆、角色阶段、认知和逻辑时间八组字段与备份一致；约 12.9 秒完成本机加载检查。
- 私有产物在工作区 `runtime/r1-20261019/`，不进入公开仓库。它是同机恢复基线，不是远端或异地备份。密钥需另行按本机配置恢复。

复用命令（在仓库根目录，输出目录必须全新）：

```powershell
python scripts/checkpoint-local.py --database apps/deskbot-service/data/deskbot.sqlite --output ../runtime/my-new-checkpoint
```

有自定义 Git 路径时传 `--git`。恢复包必须先在隔离目录核对再接服务，不应覆盖仍运行的正式库。

## 等饭诊断：为何还不能进入角色美术定稿

本批冻结的实际存档中，长桌饭食为 0，13 人中 11 人食欲指标大于 0.9；仍有真实备餐/运输计划。部分 `meal_wait_started_at` 来自停机前，因此只保留记录时间，不换算成连续在线等待时长。

`scripts/diagnose-life-wait.mjs` 读取这份只读备份，在内存中使用现有有限执行器，保留库存、人物、路线、任务、关系和义务，关闭模型选择及新连续认知作为明确的规则对照。模拟 6 小时、每 5 分钟调度一次，0 模型调用，不写回正式人生。

| 模拟时间 | 极饿人数（食欲 > 0.9） | 完成用餐累计 | 长桌剩余饭食 |
| --- | ---: | ---: | ---: |
| 起点 | 11 | 0 | 0 |
| 1 小时 | 11 | 0 | 0 |
| 2 小时 | 11 | 0 | 3 |
| 3 小时 | 9 | 2 | 0 |
| 4 小时 | 8 | 3 | 2 |
| 5 小时 | 5 | 6 | 0 |
| 6 小时 | 3 | 8 | 1 |

共完成 3 次做饭、8 次用餐、91 次等待检查。规则链可以逐渐解除短缺，尚不能证明生活节奏合格；等待检查的数量也不等于有意义的活动密度。**这是从特定存档出发的加速规则对照，不是自然六小时生活，也不是模型表现测量。**

结构性线索：当前长桌进餐按设施独占，单次 10 分钟；一锅光果餐需要 20 分钟、产出 3 份，另有采集、取材、运输、送餐和社会约定争用。不能仅凭该对照认定某一个模块是唯一原因，也不能用无限库存或降低所有需要来“修复”。下一批应对分餐并发、备餐/运输承诺、等待唤醒与模型选择分别做消融，并统计每人的实际用餐、可支配时间和等待原因。

## 验证

- 后端完整回归：800/800 通过，约 216 秒；最终投影/归属修订后再跑 41 项相关回归，全部通过。
- 前端：56 文件、318 项通过；TypeScript 与 Vite production build 通过。研究回放大 chunk 的既有提示仍存在。
- 新反例：一次捕获后源世界变化、内部角色投影偷读新世界、进程重启、重复事件、混版本响应、旧请求迟到、同世界版本的新角色响应、较早存档、超时/恢复、卸载后的迟到响应。
- 正式浏览器：新状态条收到真实 3D 绘制确认；聊天框可输入，手动刷新后未发送草稿保留。短暂停服显示“连接中断 · 保留上次近况”，重启后无需重载自动恢复。没有发送测试聊天。
- 本轮诊断实验与测试均不调用付费模型；正式服务继续原有配置和既有生活模式。本批未启用新的连续认知。

## 接下来顺序

1. **R1B 核心运行记录与存储**：给任务准入、库存占用/释放、补给承诺、等待原因和模型选择保留相同操作来源；版本化数组增量、快照引用与恢复对照，保留旧库。把上述六小时窗口变成可回放基线。
2. **基本生活节奏修正**：对同一前态测量分餐/厨房吞吐、公平性、运输和任务唤醒，避免所有人长时间等同一顿饭。规则与有限模型分别验证，失败/暂停/离线各自记录。
3. **R2 奇幻日常闭环**：在基本需要和可支配时间得到保证后，完成喵呜与两位居民在镇中—风语林—水岸之间有差异的追求、回访、拒绝/求助、带回实物和后续关系。随后进行 R3 多源对照和 R4 自然跨日。

地图可继续小步打磨，但更大区域、具体角色造型和实体外壳定稿仍以生活质量门槛为前提。
