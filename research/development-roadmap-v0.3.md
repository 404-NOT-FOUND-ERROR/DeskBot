## 一条主线

```text
P1 喵呜强角色表达验收与软件基线
 -> P2 多源证据到可解释的角色方向候选
 -> P3 关系记忆与有限主动性
 -> P4 角色方向试行、确认与阶段档案
 -> P5 同一 expression intent 驱动文字 / 屏幕 / 声音
 -> P6 ASR/TTS 与 ESP-VoCat 真机闭环
 -> P7 角色方向到潮玩视觉语义与可装配外壳
 -> P8 纵向体验、工程量化与论文冻结
```

世界环境、用户输入和角色状态绝不混成一团：世界事件有自己的规则；用户提供方向信号；喵呜只能经可追溯规则形成选择、记忆和阶段变化。

## 2026-09-17 持续世界空间层增量

已加入首个 canonical 聚形域地图：聚形域桌面、潮痕旧路、低语集市、逆光林地、回声水岸。地点坐标只供客户端布局；地点事实、邻接路线、旅行耗时、NPC 位置、当前地点和事件封路均归 Node canonical world 所有。`GET /api/world/map` 是派生读模型，`POST /api/world/travel` 必须转成 `move_protagonist` mutation，成功旅行推进逻辑时间并产生第一人称抵达反馈。LLM 文字、浏览器 DOM 和用户一句命令都不能绕过规则移动角色。

Web 地图支持点击地点聚焦、区分当前/可达/需中转地点、显示 NPC 与事件影响，并从相邻地点发起旅行。在空间骨架之上，世界自动生活 V1 已完成：正式服务按 30 分钟真实时间槽，根据当前位置、逻辑时间段、世界线和天气选择有限 Scene；Scene 和 NPC 行动先写 canonical mutation，再进入故事窗、地图和 prompt。网页刷新本身不推进世界。

下一阶段按以下顺序补强世界存在感：

1. 地点生活切片（V2 已完成）：五个地点各有三条有限日常；当前 Scene、感官细节、未发生机会和最近历史可回放。同事件可跨槽延续，最近模板有冷却，不再每半小时机械重播。下一步把世界线结果接成真正的 Scene 因果分支。
2. NPC 在地行动（V2 已完成）：两个首发 NPC 有档案、当前行动、同地点相遇面板和五种受限互动；有限目标已能沿相邻地图移动，内置日程会形成抵达与离开。下一步扩展多步等待、失败、改道与支线后果。
3. 主线/支线场景：正在发生的事件绑定地点、参与者、机会和未解钩子，形成 Character.AI 式第一人称经历，而不是后台世界摘要。
4. 地图事件反馈：封路、开放新路径、季节变化必须由世界 mutation 产生，并保留历史；用户只能影响选择方向，不能直接覆写世界规律。
5. 长期演化闭环：经历和关系只作为角色方向证据，经候选、试行和明确阶段决策后才影响身份、表达、声音、表情与未来外壳。

验收门槛：旅行与 NPC 行动可回放且重启一致；用户/LLM 无法越权移动；页面在桌面和手机不遮挡主对话；同一地点至少出现三种由状态驱动的具体生活切片，且不会每轮机械播报。

客户端方向已修订为“Character.AI 沉浸故事 × WorldOS 持续世界”：默认第一屏是像素奇幻地图而不是研究仪表盘；喵呜的第一人称故事浮在左上，输入固定在底部，其他系统作为游戏面板叠加。地点已加入按需 Scene 锚点、感官线索和未发生的 possible beats；当前生活 Scene 和同地 NPC 已进入同一检索层。页面加入“人物”入口、此地横排角色、首次相遇自动呼出、关系状态与受限互动；NPC 回应独立署名，不伪装为喵呜。

方法参考：Character.AI 的 [Lorebooks](https://support.character.ai/hc/en-us/articles/52739596326811-Lorebooks)、[Scene Creation](https://support.character.ai/hc/en-us/articles/41918454359451-Scene-Creation-Quickstart-Guide) 与 [Creator Guide](https://support.character.ai/hc/en-us/articles/50608794517915-1-Welcome-to-the-Creator-Guide)。只迁移“常驻人格、按需知识、当前场景”三层分工，不把生成文本当作世界事实。

## P2：多源证据到角色方向候选（3-7 天，核心聚合器已完成）

**目的：** 输入影响喵呜未来会倾向于成为什么，但没有任何单条输入能直接改人格、外壳或世界。

来源只冻结为：虚拟世界线、外部事实、真实时间/天气、用户稳定偏好、关系事件和设备状态。每条证据须有 `source/layer/confidence/occurred_at/observed_at/provenance/decay`。

已完成 `fantasy-pull.v0.2` 四类奇幻方向聚合器、跨源证据门槛与输出证据隔离，并接入 `/api/roles/pulls` 与研究 Web。角色回复、语音/传输输出和设备生命周期输出不再反向塑造候选；旧提案保留为审计历史。界面分开显示候选方向、证据来源、提案状态和试行反馈；原始输入与 mutation ledger 仍从独立视图回读。

**G2：** 三组固定事件序列可回放，结果一致；单句“你变成……”无法直接改变阶段；每一处方向变化可追到 evidence ID。

## P3：关系记忆与有限主动性（1-2 周，提案生命周期入口已完成）

**目的：** 让共同生活能积累，而不是用假记忆冒充关系。

- 长期记忆准入、来源、回调、更正、遗忘、冲突和敏感信息边界；
- 主动交流必须记录触发原因、相关性、冷却时间、被忽略次数和打扰成本；
- `role-direction-proposal.v0.1` 已将 P2 候选转换为可回放的主动提案，用户可 `try/later/reject`；选择已持久化并明确保持 `trying/deferred/rejected`，不自动变成 accepted。
- 角色可基于稳定证据发起一次轻量邀请、回调承诺或提出小选择，不能为刷存在感打断用户；
- 用户对角色的反馈成为方向材料，而非人格写入命令。

**G3：** 记录过的关系事实可跨会话正确回调并可更正；未记录的不被声称记得；主动性有理由、可关闭、不过量。

并行世界工作：世界线事件已支持 `daily_consequence/opportunity/unresolved_hook` 并进入 Web 和 `DESKBOT_LIVED_WORLD`。下一步不是继续堆 lore，而是建立事件延续/解决、NPC 行动和每日生活切片的自动调度与冷却。

## P4：角色方向试行与阶段档案（1-2 周，有限试行已实现）

**目的：** 真正做出“它会变成不同的它”，而不是换一份提示词。

建立 `observing -> candidate -> trying -> accepted/rejected/deferred -> archived` 状态机。当前已实现提案 API、有限窗口、正负/中性反馈累计、幂等观察、明确完成/回退、阶段历史和活动试行表达覆盖，并在研究 Web 可操作。送入对话的试行信息已压成唯一第一人称生活倾向，不暴露多个方向、ID、分数或 overlay；试行结束后立即失效，仍不会自动改变 Soul、世界或外壳。后续接入长期 `role-state.v1`，再让确认结果改变说话、主动性和偏好权重。LLM 正文没有写入权。

**G4：** 一个候选的证据、试行记录、确认/拒绝理由和旧阶段档案可完整回放；世界环境未经世界行动不变。

## P5：统一表达意图（1 周，基础合同已实现）

**目的：** 不让文字像难过、屏幕像开心、声音像播报。

已定义并接入版本化 `expression_intent.v1`：`mode/intensity/pace/prosody/expression/interruptibility/evidence_refs`，并在输出计划中同时提供 text/screen/TTS consumer 字段。文本、屏幕和 TTS consumer 已消费基础状态与活动角色试行覆盖；真实屏幕动作、TTS 参数和统一回放仍待假设备与 sidecar 验收。严肃事实和风险由同一输出路由收敛。

**G5：** 六种表达意图在假设备上可回放；同一回合三端不冲突；未连接设备时不宣称动作发生。

## P6：ASR/TTS 与 ESP-VoCat 真机闭环（1-3 周，依赖固件 agent）

**目的：** 跑通“按键/触摸录音 -> ASR -> 喵呜 -> TTS -> 播放/表情 -> ACK”的一次且仅一次链路。

- 先批处理短录音，再决定是否投入持续流式和 barge-in；
- ASR 比较 sherpa-onnx 基线与目标机可用候选；`s1-mini` 属于 ASR，不作为 TTS；
- TTS 优先验证 CosyVoice 的中文清晰度、首包、RTF、音色一致性和可控韵律；只有实测胜过候选才升级；
- 和固件 agent 冻结 `hello/capabilities/event/command/audio/ACK/error/reconnect`；固件不得保存世界、人格或密钥。

**G6：** 20 次语音回合各只进入一次会话，无双重播放；播放失败、重复命令、断网和恢复均可解释；延迟只报告目标机实测值。

## P7：角色方向到潮玩视觉语义与可装配外壳（4-8 周）

**目的：** 让“大体感变化”不止存在于文本，同时满足机械双盲中的工程量化。

从 P2-P4 导出三组差异显著的 `visual_semantics`，再映射到轮廓、比例、材质、配色、配件和屏幕语言。电子内核、接口、公差、质量、重心、声学、温升和运动包络先冻结；外壳改变必须共享核心接口。每壳记录角色阶段、证据、CAD/STL、材料、参数、质量、重心、装配时间与返工。

**G7：** 三组壳共享内核，可打印、装拆、识别；角色-外壳匹配出现可辨识趋势；至少一个代表壳通过工程级装配、稳定、热和声学验证。

## P8：纵向体验、工程量化与论文冻结（2026-12 至 2027-06）

**目的：** 回答“第 30 天为什么还愿意回来”，而不只展示一次好看的对话。

- 小样本纵向/日记研究：主动回来、角色可辨认、关系连续性、惊喜、打扰与厌烦；
- 实验：可解释演化、角色-外壳匹配、换壳/旧壳历史体验；
- 工程：装配、质量/重心、声学、热、稳定、端到端延迟、命令可靠性；
- 冻结源码 commit、模型/provider、规则/接口/固件版本、CAD/STL、BOM、打印参数和匿名数据。

**G8：** 三次完整连续旅程演示；每条论文结论能指向实验、日志、制造记录或明确限制；2027 年只做实验、分析、论文、展示和阻断性修复。

## GitHub 协作规则

- GitHub 仓库是代码、接口、研究协议和可复现里程碑的唯一协作锚点；SQLite、密钥、音频、模型、个人日志和下载缓存不提交。
- `main` 只接收可运行基线；日常从 `feature/`、`fix/`、`research/`、`docs/` 分支经 PR 合并。
- 每个 PR 必须写用户可见变化、canonical state/迁移影响、测试、真实模型或页面验收、固件影响。
- Actions 必须跑服务回归；角色变化必须附 P1 样本记录；接口变化必须同步 `interaction-contract` 并通知固件 agent。
- 最少四个 tag：`software-baseline`、`device-loop`、`shell-study`、`thesis-freeze`。

新增 `story-packages.mjs` 与 `/api/life/story-packages`。内置三日「潮后寻路」包，先预览后显式安装；安装生成世界事件、巡路员 NPC、NPC 开路行动和第三日后果四个有序步骤。安装返回 `causal_chain`，每一步包含 evidence ID、来源层和前置依赖；同版本重复安装返回冲突，不写重复计划。预览不会改变 canonical world。新增 `story-packages.test.mjs` 覆盖无副作用预览、版本目录、幂等安装和因果链。

这一步借鉴 Character.ai 的 Lorebook（按触发相关性注入背景）、Scene（固定开场状态与可继续钩子）和 Greeting/example dialogue（用具体示范承载角色表达），但保留 DeskBot 的 canonical mutation、用户显式安装和证据可追溯边界。后续需把三日包接入 NPC 目标、确认记忆和角色候选证据，而不是把一次故事包当作长期生命感证据。

### 目标四开放方向增量

`fantasy-pull.v0.3` 现在接受作者/输入源提供的结构化 `role_direction` 或 `direction_hint`（`direction_id/label/life/cues`），并与内置方向使用同一套跨来源、最小证据量、置信度和衰减规则。相同方向会按 ID 合并，缺少两条以上 cue 的低质量条目会丢弃；单一输入仍不会进入候选。动态条目只产生 `observing/candidate` 读模型，仍必须经过提案、试行和明确决定，不会写入 Soul、外壳或世界。

新增 `shared-life.mjs`，使用已有 SQLite records 持久化，不改固件、不迁移用户存档、不增加外部 API 费用。

- `GET/POST /api/life/memories`：显式确认的关系笔记，带来源引用、角色隔离、修订和物理删除；最近 20 条进入对话上下文。不是自动提取或完整长期记忆系统。删除只移除该记忆记录，既有聊天/审计记录不随之删除。
- `GET/POST /api/life/plans`：作者登记按真实时间触发的有限世界事件/NPC 计划。服务每分钟执行，启动补进度，每轮最多三步；同一事件 ID 幂等，失败阻断该计划后续步骤。计划不是用户角色命令，不能写偏好、人格或外壳。
- 世界步骤进入现有 input/world/evidence 管线；记忆只进入只读上下文，不自动变成幻想方向证据。没有登记计划时世界保持原状态，不注入示例覆盖真实世界。
- 自动测试使用隔离 SQLite 和模拟时钟，不伪造真实跨天体验；后台 API 已接入，网页编辑入口、语义记忆检索、计划取消/修订、NPC 自主目标和角色自主试行决策仍待完成。
- 下一验收：先给编辑入口与一个可选择安装的三日世界/NPC 事件样本，再检查回调与候选因果链；之后真实跨天验证。不得把调度器当作完整自主世界，或把测试全绿当作生命感证明。

## 2026-09-17 世界自动生活与 NPC 相遇 V1

- 新增 `world-life.mjs`、`GET /api/life/world` 和 `POST /api/life/npc-interactions`。正式服务启动播种「潮痕巡路员」「影栖」，每分钟检查当前 Scene；GET 只读，不因页面刷新产生 mutation。
- Scene 由有限目录确定选择，字段包含地点、标题、叙事、感官线索、尚未发生的机会、参与者、来源因子和起止时间。每地点三条模板用于验证状态驱动生活，不代表开放生成世界。
- NPC 只有与喵呜同地点时才能 `observe/greet/suggest/help/invite`。用户想法最多 500 字，只影响这次受限回应；不能直接命令 NPC 移动、改世界、改身份或改外壳。互动有幂等键和有限关系增量，可回放、可重启。
