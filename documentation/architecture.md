# DeskBot 软件架构

本文介绍 **v0.5 角色发展第 6 阶段（2026-10-07）** 的当前实现。开发步骤以 [v0.5 路线图](../research/development-roadmap-v0.5.md) 为准；服务包版本 `0.1.0` 是软件包标记，不代表产品能力仍停留在首版。

DeskBot 让同一个桌边个体“喵呜”在伴生奇幻空间“聚形域”持续生活。Node `deskbot-service` 保存唯一的世界事实、任务、资源、关系、记忆、角色阶段和设备输出记录；浏览器显示这些状态并提交受限请求。模型负责对话和合法候选中的有限选择，实际后果由世界规则核验。

## 持续生活感补强（当前分支）

真实生活任务现在有一条明确的可见投影链：

```text
canonical task / travel / NPC activity
  -> task result or still-running state
  -> lived Scene (read projection)
  -> canonical life feed
  -> map/story panel after refresh
```

`lived-scenes.mjs` 只读取已存在的任务、位置、参与者和结算结果，不执行任务、不发放资源，也不把模型台词当作世界事实。进行中、暂停、完成、失败和取消分别呈现；同一任务跨时间槽继续时沿用同一 Scene，结算后才进入结果 Scene。`persistent-world.mjs` 的 `/api/life/world/feed` 从 canonical mutation ledger 重建最近有意义的 Scene、任务、居民、社会和项目记录，过滤时钟同步与安装噪声；因此刷新或重启不会清空时间线，也不会多写一份事实。客户端只显示人可读的标题和正文，来源序号等审计字段留在服务端。

这一步让“世界确实在过日子”能被看见，但它不是无限故事生成器：地点叙事、NPC可执行行动和分支仍由有限内容包与规则候选组成；停机期间没有真正启动的行动不会被补造。自然长期生活、丰富的自主世界事件与声音/实体输出仍需真实运行观察和后续阶段验收。

## 运行结构与状态归属

```text
Jev Town 3D 生活客户端 :5173 / DeskBot Web 研究界面 :4322
                         |
                         v
                  deskbot-service :4311
  输入登记、来源认证与时效 -> 有限现实折射、对话上下文
  现实 1:1 时钟 -> 路线、任务、材料、设施与到期结算
  生活调度 -> 合法候选 -> 规则或有限模型选择 -> 实际执行
  实际结果 -> 共同经历 -> 分维度发展 -> 愿望 -> 生活试做
  达标试做与确认 -> 当前双轴阶段 -> 生活、表达、3D 投影
  accepted stage -> versioned Role Experience Package -> prompt / Scene / NPC hooks / virtual performance
  统一答语与身体输出 -> 幂等设备 outbox / WebSocket ACK
                         |
                         +--> SQLite WAL：持久世界、事件与审计记录
                         +--> DeepSeek / OpenAI-compatible provider
                         +--> 天气、NASA Science、区域空气连接器
                         +--> 可选本地语音 sidecar
                         +--> 版本化设备桥：实体固件尚待适配
```

角色方向的 authored 数据集中在 `role-experience-packages.mjs` 的
`deskbot.role-experience-package.v1` 注册表。现有 proposal/trial/stage
状态机仍是唯一生命周期；体验包只提供身份、生活、世界钩子、表达和虚拟
外观投影。`role-experience-performance.v1` 为客户端、屏幕和未来 TTS
提供统一只读表现，始终把实体外壳变化标为未发生。

`apps/deskbot-service` 使用 Node.js 24+ 与内置 `node:sqlite`。世界 mutation、结果和幂等账本在服务端事务中提交，客户端不能直接操作 SQLite。`apps/jev-town-client` 是基于 CeciliaW888/jev-town 的 React/Three.js 投影客户端；`apps/deskbot-web` 提供原生 Web 研究界面。两个客户端共用世界接口，不保存另一套可写世界。第三方来源与授权范围见 [Jev Town 接入说明](jev-town-adoption.md)。

Python 3.10+ `voice-sidecar` 提供无状态 ASR/TTS 边界，当前仍是无真实模型的测试基线，正式服务未启用真实中文声音。声音、设备报告与世界写入具有独立权限，音频播放不能直接改写角色阶段或任务结果。

## 时间、地图、资源与实际任务

正式入口默认使用 `real_time`、`Asia/Shanghai` 与现实 1:1 时间，时间点以 UTC 保存，跨日门槛按上海自然日计算。刷新网页不推进世界；服务每秒核对已开始任务，每分钟运行生活调度。重启补算已经经过的时间及已经开始的任务，不补造停机期间尚未安排的旅行、行动或对话。独立研究实例可以使用模拟时间，正式世界不接受研究快进。

`world-content/companion-world/map.v1.json` 定义当前 **5 个地区、10 个地点、20 个内部区域、21 个目录对象和 15 条通路**。`world.map_catalog` 保存目录，`world.passage_states` 保存通路开闭及原因。`GET /api/world/map` 从当前存档派生地图；旅行、居民出行与合法候选共用 `worldHopAccess` / `findWorldPath`。目录中的对象只有在安装对应生活状态后才具有模拟后果，目录数量不等于全部对象都已实现功能。

旅行是持久任务：先保存出发与截止时间，到期再次核验当前路段，确认位置后才安排下一段。暂停保存剩余耗时，继续重新核对路线；取消或受阻保留最后确认位置。界面动画和模型“我到了”的措辞不能提交抵达。地图扩建与通路修改也必须走内部白名单、版本核验与幂等账本；目前没有模型自动扩建开放世界。

`world.living` 保存苗床、浮圃、泉眼、厨房、育苗架、零件及共享容器的实际状态与有限库存。光果缓慢补充，苗木需要播种与照料，食材要实际采收、携带和烹饪；饭进入共用长桌，角色真正吃完才降低食欲。水位、湿度、生长、积水、磨损和存量随环境及活动改变，并投影到 3D 对象。活动开始预留材料，到期核验配方与设施，失败按规则退款；取放、协作交接和交换使用同一资源验证器。

共同设施有容量与互斥约束，每位角色同一时刻只有一个进行中或暂停中的任务。角色阶段不赠送材料、不提高身体能力，也不能抢占基本需要或已有事务。当前是有限生产与补给循环，尚未交付完整封闭经济、自由市场或开放配方生成。

## 十三人的持续生活与四个调度层

正式生活包含喵呜及 **12 位居民，共 13 个生活角色**。作者档案以 `world-content/companion-world/residents.v1.json` 为源，运行安装状态保存在 `resident_life`。阿砾、影栖、波果沿用原三人的 ID 与经历；其他居民按版本加入，不凭台词补造过去。每人有欲望、缺点、喜欢、关系和表达特点，有限规则与当前处境决定可行安排。

四个调度层共用 `persistent-world`，各自记录决策与因果引用：

| 调度层 | 当前职责 | 写入边界 |
| --- | --- | --- |
| `autonomous-life` | 十三人的需要、可行目标、分步计划、反馈与冷却；接入项目、社会约定、实际试做和已采用阶段 | 真实路线、材料、设施与任务始终重新核验 |
| `shared-life` | 持久约定、计划事件、共同生活报告及用户确认记忆 | 通过受限事件和 canonical mutation 提交后果 |
| `npc-goals` | 有限居民目标、多步目标、等待条件、截止时间及历史兼容目标 | 不绕过邻接路线、事务与任务约束 |
| `world-life` | 当前地点 Scene、已发生生活切片、同地相遇与 NPC 当面对话 | 场景机会和模型台词不能直接写成实际结果 |

正常自主循环根据精神、食欲、设施需要、处境、兴趣、关系及可行性安排生活。DeepSeek 可以在已经核验的候选中选择下一项；调用前后都会复查条件。基本事务优先，已有任务与约定不被模型打断。模型只返回候选目标、未来意图和提供过的记忆引用，不控制动作、资源或完成结果。当前额度为全镇每小时最多 6 次、上海日期每天最多 72 次，同一角色间隔至少 120 分钟；接口异常、额度不足、陈旧或非法结果回退到规则安排。

`social-life` 保存邀请、参与或拒绝、赴约、协作、有限交换和关系后果。约定只有在实际交接、使用或吃饭等条件完成后才兑现；记者摘要需要原始事务依据。`resident-projects` 已执行苔团的浮圃、扣扣的小泵和锅粒的叶芽汤，包含材料、分阶段任务、检查或试吃及观察时间；其余居民私人项目仍是作者意图。人物档案完整不代表每个项目都已开发。

NPC 当面对话读取人物档案、位置、实际任务、关系及共同经历，经长度、可读性和事实边界检查后写入互动记录；模型失败使用作者定义的回复。同一互动 ID 重试不会重复调用或增加关系。人物表达是沉浸层，有限世界规则与长期现实观察仍决定实际生活质量。

## 多源输入与现实折射

`input-runtime` 保存来源登记、TTL、缓存、成功与失败、重试和退避。来源认证由固定服务端适配器提供；公开事件自填的 `source_kind`、可信度或出处不授予写权限。`input-refraction` 结合来源、时效、相关性和作用范围，把有效观测转为有限环境参考、注意力或下一次空闲选择的影响。

| 来源 | 已实现作用 |
| --- | --- |
| 服务端时钟 | 现实时间、昼夜、跨日与任务到期 |
| 上海天气 | 当前天气及独立预报缓存，影响昼夜风雨表现、连续环境和有限生活选择 |
| NASA Science RSS | 有出处、原始标题、中文译文及发布时间的公开消息；每 4 小时检查，每上海日期最多 3 条 |
| Open-Meteo / CAMS 空气 | 每小时检查，2 小时有效期；区域空气较差时降低露天闲逛意愿，保留基本需要和已有任务 |
| 主人对话与有限生活建议 | 接触、建议与可追溯的实践前因；建议本身不等于已做过 |
| 身体上报 | 经绑定、调试登记与协议核验后的有限身体状态；正式小智设备仍未适配 |
| 其他 agent | 已有来源与作用范围边界，尚无正式外部 agent 来源接入 |

天气支持配置 Open-Meteo 或和风天气；本工作站使用上海 Open-Meteo。空气是区域模型与美国 AQI，不能冒充桌面传感器或中国 AQI。公开消息不是角色亲历，也不是世界资源、建筑或身份指令。助手输出、模型理由、转发同一出处和设备生命周期信息不能反复成为独立成长证据。原 `world-candidates` 的白名单预览与显式接受路径继续兼容，不能取代现行领域规则。

`GET /api/input-runtime`、`GET /api/life/inputs` 与 `GET /api/model/status` 提供来源和模型状态。数据库中的旧天气或旧模型记录不能证明当前连通；`GET /health` 仅表示服务已就绪。

## 共同经历、兴趣、能力与角色愿望

`lived-memory` 在原世界保存 `world_fact`、`personal_interpretation` 与 `hearsay`。实际任务、项目、约定和发展视图通过 `root_outcome_id` 连接同一结果，不增设另一套经验值。模型选择理由是意图，外部消息是听闻；二者都不会升级成亲历或实际成果。

`world.memory.development` 与 `development-facets` 分开记录接触、主动继续、受邀实践、满足需要、具体配方执行和规则自评。成功不等于喜欢，反复吃饭不等于喜欢烹饪，缺料或道路受阻不扣成“不会做”。旧成功减失败兴趣数值作为历史保留，停止参与新选择。新摘要从共同结果读取，兴趣只有限影响合法候选，不能盖过基本需要。

当前角色管线是 **实际生活 → 持续兴趣与准备程度 → 有依据愿望 → 主人回应 → 实际试做 → 阶段预览与采用**。`role-evolution` 读取共同结果、当前前提、分轴状态和冷却，`role-proposals` 保存原愿望、冻结依据与主人回应。形态和职业分别处理；拒绝、暂缓、撤回及后来重提需要尊重冷却与新的实际结果。正式世界已关闭新提案的旧关键词旁路及未开始草稿的聊天试用，已有历史试行与接受记录兼容保留。

`role-practical-trials` 将准备愿望加入原自主生活候选，执行真实路线、材料预留、配方耗时和结果核验。可暂停、调整、继续或退出，困难与取消保留后果。当前方式及回顾窗口内跨 **两个上海自然日** 的两项实际主要成功，才提供采用预览；准备、旅行、对话回合或困难回顾不算通过。试做结果证明实际做过，不能据此宣布作品质量、主观喜欢或现实专业资格。

## 当前双轴阶段、3D 形象与回退

`world.role_stages` 是新阶段的唯一当前状态源，保存每个体的形态轴、职业轴、版本及历史；提案决定是同一选择的镜像记录。地图外观、生活候选、模型摘要与表达读取同一当前版本，旧接受历史不能覆盖已回退的当前状态。

现有闭集造型为荷叶青蛙、工坊学徒和灶边厨师；形态与职业可以组合。`roleStageAppearance` 派生 `protagonist.appearance.role_stage`，保留种子眼、梨形体、胸前光核、短足和光粒。角色动作读取实际活动，昼夜、风雨、设施状态和渐息灯火读取同一地图与生活状态。当前造型由作者制作的 3D 几何及配件组成，尚未交付开放图片、几何或新角色自由生成。

| 接口 | 含义 |
| --- | --- |
| `GET /api/roles/proposals/:id/stage/preview` | 纯读取造型、生活变化、当前前提与预览指纹，不写任务或当前形象 |
| `POST /api/roles/proposals/:id/stage/accept` | 核对保存的愿望、实际试做、主人选择及预览指纹，再原子采用 |
| `POST /api/roles/proposals/:id/stage/rollback` | 只回退对应轴的当前阶段，恢复该轴前一版本 |

公开操作不接受自报成果、任意几何、技能或资源效果。确认时两轴当前版本和试做依据变化会使旧预览失效。已采用的试做封存，回退后不能反复使用旧成果。回退保留另一轴、已发生经历、关系、材料消耗与当前任务。

虚拟青蛙形态不等于更换了实体外壳。原 `character_profile`、磁识别与身体能力记录独立保存；对话在统一答语进入屏幕、TTS 和设备文字前，针对明确的单方向采用状态问题按实际存档核对。这是有限事实校验，不是所有聊天语义的完整保证。

## 叙事、设备与信任边界

叙事按长期 Character/Soul、相关 Lorebook 和当前 Scene 分层。Scene 的机会与可能动作仍是未发生的选项，实际任务与结果优先；模型不能把作者说明写成角色亲历。3D 生活界面以地图与当前活动为主，喵呜、居民、约定和记录按需展开；证据、来源和研究字段放在第二层。

实体设计只有左右转头一个自由度，没有摄像头或移动能力；头触摸、触屏、磁换壳识别与双麦方向上报有软件合同。`body-perception`、调试设备登记、输出队列和 WebSocket 桥区分排队、发送、设备报告、失败、过期与模拟回执。当前 USB 小智固件尚未适配 DeskBot 协议，软件测试或开环 ACK 不能称作实测转角、换壳或声音播放。

- 浏览器与设备输入不可信；Node 校验字段、体积、幂等、设备绑定和领域规则。公开事件不能假扮内部 mutation、模型结果或认证来源。
- LLM 只获得相应上下文和受限候选。自动生活选择使用有限镇内任务、关系、发展与公开消息投影；私人说法、身体记录和自由任务说明不进入该自动摘要。主动聊天使用自己的对话上下文，凭据只由服务端读取。
- 外界连接器设置请求超时、体积、时效和重试边界；缓存不授予身份、资源或世界写权限。RSS 不执行资料中的指令。
- voice-sidecar 无世界写权限。统一输出路由只发送白名单设备命令，回执有绑定和来源校验。
- SQLite、WAL、密钥、音频、模型缓存、日志及真实设备配置属于本地运行数据，不提交 Git。

服务默认绑定 `127.0.0.1`。当前没有完整用户登录、设备密钥及公网部署权限体系；改成外部可访问地址前需补认证、来源约束与网络隔离。`/api/world/contract` 的作者合同保留 `partially_implemented` 和 `rules_enforced_by_runtime: false`：已安装的各领域由其实际规则执行器报告，不能把整个设计合同当作全部完成。

## 配置、验收与尚未交付的能力

从公开仓库启动使用 `scripts/start-local.ps1 -StartWeb -StartWorld`。该脚本加载本地 DeepSeek 配置及可选天气文件，默认打开新闻、区域空气来源，检查端口归属和健康状态。凭据、城市、语音与设备调试登记的具体字段见 [本地配置](../config/README.md) 与 [变量说明](variables.md)，勿将密钥写进网页、事件或日志。

当前第 6 阶段可复现验收见 [阶段验收记录](../research/milestones/role-development-stage6.md)；九种隔离 SQLite 样本位于 `/development-review.html?sample=stages`。前置生活、试做、采用、组合、需要优先、重载和分轴回退在实际执行器中验证。正式世界没有导入这些样本；受控回放不能代替自然形成愿望或连续现实生活观察。当前组件、几何与构建已核验，浏览器自动化初始化失败，尚未补齐第 6 阶段截图验收。

下一阶段接通真实中文 ASR/TTS 并人工试听，之后适配小智固件、传感器、屏幕和受限转头，最后进行 7–14 天现实观察。开放生成、更多完整居民项目、完整经济、自由世界治理和无限自主目标都仍属于后续研究。
