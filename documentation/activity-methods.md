# 活动方法接入规范

本规范落实 [开发基线](development-baseline.md) 的 R3-A 第二轮。当前以三种真实活动建立共同接口，后续按同一边界迁移其他内容。

## 一份定义的使用链

`contracts/activity-methods.v1.json` → `activity-methods.mjs` 校验并只读加载 → `living-resources` 活动与执行检查 → 当地人物的 `methodView` → 认知选项 → 原任务执行器 → 完成证据 → 事实记忆和发展账本。

Python 接收 Node 生成的当地机会、条件和目标 ID，绑定本人选择；不在 Python 再实现一套库存、天气或灯具规则。Node 提交时对照冻结选项和当前状态，执行时继续检查条件。接口索引见 [架构登记](../contracts/architecture.v1.json)。

## 方法定义

| 字段 | 责任 |
| --- | --- |
| `id`、`version` | 稳定的方法身份和行为版本；名称、故事或个人动机不是方法身份 |
| `topic` | 实际实践所属主题，沿用现有兴趣/能力账本；不直接授予爱好、技能等级或角色 |
| `executor` | 已注册的执行机制；目前为普通固定配方 `recipe`、已有归途灯适配 `waylight`、只测记的 `sample` |
| `recipe` | 目标、耗时、消耗、产物；由执行器读取，不接受模型自报效果 |
| `conditions` | 白名单字段的存在、相等或数值阈值检查；与位置、权限、占用、恢复、材料、容量检查共同生效 |
| `method`、`effects`、`limits` | 说明实际做法、可能作用和不能推导的结论；用于认知与审阅 |
| `observations` | 可记录的现场字段及名称；不允许访问别人的背包、记忆或任意表达式 |
| `experiment` | 可验证问题、真实对象身份和有意义的条件轴；普通生产填 `null` |

三种迁移实例：

| 方法 | 执行 | 产物 | 实验与发展依据 |
| --- | --- | --- | --- |
| 泉眼汲水净滤 | 10 分钟，4 份原水 | 4 份清水 | 普通照料；不提供归途灯证据 |
| 借归途灯净滤 | 5 分钟，4 份原水；保留原灯具规则 | 4 份清水 | 同一灯具及罩片状态下实际使用；主题仍为照料 |
| 水岸测记明暗 | 3 分钟，零物料 | 无 | 记录亮度、蓄光和湿润度；主题为观察，不调整灯具 |

新测记活动通过通用 `sample` 执行机制接入。认知绑定、记忆、兴趣模块没有加入它的活动名称特判。尚未迁移的活动继续使用既有规则；特殊地区规律必须提供有明确输入输出的执行适配，不能仅填一段文字就获得世界修改权限。当前 `waylight` 适配仅接受已有借灯净滤方法。

## 条件、用途和证据

实验条件键由方法 ID、行为版本、真实对象 ID 与登记的条件轴生成。本轮条件轴是罩片位置、是否已有罩片、昼夜阶段。自然亮度或蓄光的小幅漂移、时钟字符串、研究名称和人物理由不生成新实验键。天气和其他地区规律的有效条件轴仍需在后续规则适配中明确设计，不能把任意外来新闻直接当成条件变化。

每名人物按条件键保留首次实际完成的结果根。它与近期任务列表、未完事项标题独立保存；另一人物不会继承这份亲历。相同条件已有证据时，不再提供重复实验用途。罩片或真实对象变化后可以出现新条件，但仍需满足夜间、可用光照、间隔、材料、容量等执行规则。

普通生产继续允许有限备用、真实自用、已接受交付。实验去重不会禁止为明确用途再次取水；背包已有足量时，程序也不会把普通取水包装为新研究。测记没有消耗品用途，重复条件下只保留普通查看等其他选择。

`finite-use-v1` 的用途结构保持兼容，新增判定版本 `experiment_rule: method-conditions-v2`。实验选项同时绑定一批产量、本人事项和对应条件的完成目标。模型只选选项；程序不从自由文字猜其方法。

开始时，执行器保存 `deskbot.activity-method-binding.v1`：方法版本、定义指纹、开始时间、对象、条件键及观测起值。只有实际成功结算后才保存 `deskbot.activity-method-result.v1`，包括同一结果根、结束值、实际库存变化与解释边界。任务期间更换对象或罩片、定义版本不一致会导致失败与退料，不把混合条件记成原实验成功。

完成目标使用 `method:<方法ID>:<条件键>`，并核验结果中的方法版本与条件键；另一个条件的成果不能替它完成。结果根继续进入现有事实记忆、共同发展账本和未完事项的证据链。一次观测或生产记录不证明单独因果，不等于人物已形成稳定兴趣。

## 兼容与恢复

- 原存档无需批量重写。旧任务没有方法绑定时，沿原规则结算，不追补新的条件证据；旧记录也不会被解释成新方法的完整试验。
- 新任务的绑定、结果及按人物保存的条件证据跟随原 SQLite 世界事务持久化。重启继续原任务，重复结算不能增发产物或证据。
- 取消和条件受阻保留各自结果，退还已预留材料，不写成功条件证明。
- 同 ID 的行为改变必须显式更新版本并提供迁移说明。名字或说明的编辑不会改变条件键，但开始后定义指纹变化会阻止混用两份定义结算。

## 扩展时的检查

同类新活动应只增加作者定义与案例；新增执行规律才增加适配代码。必须验证正常完成、资源不足、用途已满足、重复条件、新条件、途中变化、取消、状态过期、重启及人物可知范围。需证明真实结果进入记忆与发展链，不能只验证 JSON 可加载或菜单多了一行。

统一运行 `npm test`。第二轮未统一所有后续事项、短期目标和地区内容包；这些入口仍需第三轮及 R3-C 继续迁移。当前通用观察与配方也不代替最终奇幻活动内容的丰富度。
