# 目标连续性与位置知识（A2）

版本：2026-11-01。依赖 [机会目录](cognitive-opportunities.md) 和 [公共事件证据](cognitive-event-evidence.md)。共享合同为 [目标生命周期](../contracts/cognitive-goal-lifecycle.v1.json) 与 [位置知识](../contracts/cognitive-position-knowledge.v1.json)。这些是版本化语义合同，不是完整生活协议的 JSON Schema。

## 唯一状态归属

沿用 `life.state.short_term_goal_entities` 与 `life.goal_bindings`。Python 的 Asamana 需要层仍计算动机，适配器提出目标转换；Node 在世界提交前复核。没有新增数据库、第二套规划器或直接执行模型文本的入口。

| 字段 | 含义与写入边界 |
| --- | --- |
| `goal_id` / `text` | 身份与原始表述固定；继续、换方法和恢复引用同一 ID。改变真正的完成标准须另建目标。 |
| `completion_criteria` | Node 从具体机会生成并冻结；模型只选编号，不能提交任意谓词。 |
| `binding` / `attempts` | 当前方法与有界尝试记录；`replan` 显式选择当前目录中的兼容机会。 |
| `evidence_ids` | 执行器的结果根；取消、失败、通知正文、既有库存和未执行的打算都不能补成结果。 |
| `lifecycle_status` | `active`、`postponed`、`abandoned`、`completed`；旧终态另外标记 `legacy_closed`。 |
| `next_review_at` | 个人复查时钟，1–48 小时；到期不失败、不自动顺延。 |
| `transitions` | 每次显式选择的时间与原因，最近 24 条。未了结事项最多 6 个，超限拒绝而非自动挤掉旧目标。 |

状态表是 UI/上游状态的明确映射：暂缓映射 `interrupted`，放下映射旧枚举 `failed`，但领域含义仍分别是暂缓、主动放下，**不是执行失败**。显示或统计应读 `lifecycle_status`。关闭历史最多 24 项；不会丢弃仍未了结的事项来腾位置。

## 哪些方法可以替换

第一类是 **自用清水储备**：普通汲水与借归途灯净滤共享明确的数量目标。必须由本人在绑定后的真实尝试产出对应份数清水；仅看到背包有水不算完成。这个标准不证明清水已经交给别人，也不证明灯具效果更好。

第二类是 **具体机会**：方法、用途、版本、研究条件保留完整 identity。无遮罩与有罩的测记不能混用；未经作者明确声明等价的方法不自动互换。扩展新地区时应先定义其可验证的成果标准，再决定哪些方法等价，不根据活动名称猜测。

第三类是 **结果字段送达**：冻结收件人、源结果根、摘录 ID 和字段。必须有实际送达的同一摘录；只送“测记完成”、换了收件人或引用另一份结果均不满足。

第四类是 **开放研究**：没有客观完成谓词。可以继续、暂缓、换尝试和明确放下；一次动作成功不会把“理解水岸规律”自动结案。长期兴趣、愿望和角色资格仍由既有发展账本计算。

## 转换与两个时钟

`new → continue / replan / postpone / abandon / complete`，暂缓后可 `resume`。`new`、`replan` 只在计划阶段进行；反馈可依据实际结果复查或明确完成。所有变更先在副本验证，ID、标准、方法、状态或证据不合法时不提交。

模型不能通过省略 `goal_contract` 降级新 job。当前冻结引用要求 `deskbot.goal-lifecycle.v1`；旧冻结上下文没有此合同则继续按旧规则回放。新适配器替换原有目标生成和进度判断调用，不增加一次额外目标模型调用。

个人复查与社交约定截止是两件事：新目标的 `review_in_hours` 只安排重新考虑；已接受约定的 `deadline_at` / `not_before_at` 继续由社交执行器维护。旧 `due_step` 原样保留。过了复查点只唤起一次计划；同一到期记录不每十分钟重叫模型，睡眠、低体力、实际工作和未反馈结果保持优先级。

上游 Asamana vendor 文件保持不变。新合同走适配层的 ID 转换，不走原来的近似字符串合并、FIFO 失败与六步到期清除；旧合同回放仍可验证原行为。

## 位置是有出处的线索

| 类型 | 可以说什么 | 不能推导什么 |
| --- | --- | --- |
| `seen_here` | 当前在同一地点亲见，有观察者和时间 | 未来仍在原地、私人意图 |
| `seen_before` | 上一次实际见到的位置 | 对方此刻的位置 |
| `reported` | 收到了对方自己公开的位置记录，保留消息编号、说话人、观察/收到时间 | 对方现在仍在原地，或报告等于亲见 |
| 未知 / `expired` | 可以自行去探索或询问 | 从名字、职业、住处或远处 NPC 运行状态补位置 |

30 分钟后标为 `stale`，24 小时后公开位置置空、保留出处；阈值是可调整的初始政策，尚未经自然生活校准。只在成功采用观察或实际收到的结构化自我位置报告时存入本人知识。读快照不写状态，未送出的消息不生效，外部署名信与自由文本不自动解析成地点事实。

## 兼容、验证与回退

旧目标按原 ID 迁移；已绑定的保持精确机会标准，未绑定的保持开放设想，旧完成/失败标记不补新证据。迁移在采用提案时落库，投影只读。新版状态不允许退回旧目标协议写入；软件回退前应恢复对应版本的存档备份，不让旧程序重写新版状态。

Node/Python 同一组转换反例、真实 Python 工作进程、原任务结算、实际通知/摘录及 SQLite 重启均有回归。可重跑的图表样本：

```powershell
node services/deskbot-cognition/evaluations/goal-lifecycle-check.mjs ../runtime/a2-lifecycle-check.json
```

该命令无模型调用，使用虚构隔离状态。图表和 [本轮交付](../research/milestones/a2-goal-lifecycle-2026-11-01.md) 不能替代 A3 真实模型或 R4 自然跨日验收。
