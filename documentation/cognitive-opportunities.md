# 当前选择、短期目标与后续机会

本规范落实 [开发基线](development-baseline.md) 的 R3-A 第三轮，承接 [活动方法规范](activity-methods.md)。共享版本目录为 [cognitive-opportunities.v1.json](../contracts/cognitive-opportunities.v1.json)。它登记视图版本与引用边界，语义由 Node 权威投影、Node/Python 校验和共同反例验证；不是全部生活接口的完整 JSON Schema。

## 同一处生成，多个入口读取

`世界条件 / 方法 / 有限用途 / 联系回执 → 具体选项目录 → 机会投影 → 当前选择 / 短期目标 / 反馈后的下一步`

原执行器提供材料、时长、设施、路线与地方规律；具体选项目录还核对用途、批量、实验条件、事项和收件人。机会模块只投影这些判断，不增加行动规划器或复制物理规则。

当前动作读取可执行选项。未来安排可以读取受阻但用途仍有效的机会，例如等材料或实际冷却；库存已够、同条件已有证据、同用途已联系而未回复，不会被重新包装为可执行机会。开放设想可以保留问题并填 `next_step:null`。

| 数据 | 责任 |
| --- | --- |
| `opportunities.entries` | 本人的当地机会、命令绑定、用途、条件、完成目标与适用事项 |
| `id / identity` | 具体选项 ID，以及动作、用途、事项、方法版本与条件的指纹；小幅时钟流逝不改指纹 |
| `status` | `ready` 可以考虑执行；`blocked` 有真实前置条件；缺失不自动等于冷却 |
| `continuation.next_options / wait_options` | 从机会派生的引用，以及本人实际消息和约定的等待条件 |
| `next_binding / wait_binding` | Node 保存的未来引用及条件指纹，模型不可自行写入 |
| `goal_bindings` | 短期目标与具体机会步骤的绑定；不是任务或预约 |
| `task.opportunity_binding` | 世界接纳动作时留下的机会身份，用于核对实际完成 |

未来步骤优先使用 `{kind: "opportunity", id: "给定选项 ID"}`。原 `activity/social` 简写只在当前恰好对应一个具体机会时兼容；多个用途、实验问题或收件人不能由程序任选。旧存档无法唯一恢复的引用保留原问题，进入复查。

## 等待与事项连续性

- 计划和反馈均检查当前机会。冻结引用与当前条件身份不符时报告过期，不修改原问题或假装执行。
- `wait_for` 只能指向实际未就绪条件。条件就绪、机会消失、绑定条件改变或回复等待到期，需本人重新考虑；反馈也不能用新措辞延长旧等待。
- 当前和暂存事项均保留原等待起点；恢复旧问题不会重开六小时回复期限。真实迟到回复仍可成为就绪依据。
- 下一步与所等条件须是同一机会，或消息对应的实际约定。等待回复不是再发邀请，等待交接不是再次取水。
- `ready` 不代表完成，也不强迫立即行动。个人晚些再做可以设置复查时间并清空 `wait_for`。
- 换事沿用当前/暂存事项、稳定 ID 与完成目标。未解决问题不因休息或换事消失；完成、觉得了解够了、主动放下保持不同语义。
- 调度读取条件与复查标识，已有任务优先，不将每个时钟变化当新机会。

相同联系用途按真实收件人与条件去重。实际回应到达时保存回执，避免显示收发件箱轮转后忘记回复；当前和暂存问题等待的旧消息仍可找到。超时不算答应，消息送达不算资源交付。多人对话质量和拒绝后的长期关系仍需 R3-B 验证。

## 短期目标与 Asamana

以下为第三轮 v1 的精确机会绑定。2026-11-01 新 job 使用 [A2 生命周期合同](cognitive-goal-lifecycle.md)：标准与方法分离，原绑定按稳定 ID 迁移，未了结目标不再由时间或 FIFO 清除。旧冻结上下文继续按本节验证原语义；同条件研究的精确身份边界保留。

保留原需要评分、目标队列、个人理解与反馈，在 vendor 外增加 `OpportunityNeedEngine`，替换原短期目标生成调用，不额外增加模型规划回合。每次最多两项新方向，显式选择给定机会或保留未绑定设想。历史自由文字目标按未绑定设想兼容，不从文字猜活动。

绑定在动作之前，由 Node 核对机会、个人目标身份和条件。反馈不能事后换一个容易完成的标准。世界结算才留下实际结果根；别人的活动、别的方法、取消、技术失败和目标文字均不提供完成证明。

绑定步骤证据随原 SQLite 世界事务持久化，在近期任务轮转前保留。核对本人任务、绑定时间、同一机会身份、已完成结算和冻结观察；孤立的 `completed` 标记不算证据。它只证明具体步骤，不证明更大的研究、稳定兴趣或角色愿望完成。模型对未绑定设想的评价没有世界修改权限。

新格式含未知机会或非法字段时停止回合并记录合同错误，不补模板目标。模型把已绑定步骤误标完成、执行器却无证据时，Python 保留待复查状态，Node 也拒绝没有证据的完成提案。个人放下与实际行动失败仍须区别理解。

## 扩展与验证

同类新活动接入方法和执行能力，具体用途进入选项目录，目标与后续随之读取。新等待条件须明确来源、就绪依据、超时、可知范围、恢复策略和结果权限。

覆盖用途已满足、物料恢复、条件变化、重复实验、回复到期、重复联系、显示轮转、换事恢复、目标假完成、取消和 SQLite 重启。当前选择、反馈和目标生成使用共同病例，Node/Python 不一致按合同缺陷处理。

第三轮用模拟响应及真实 Python/Node 进程验证工程链路，未调用付费模型，证据见 [第三轮交付记录](../research/milestones/architecture-round3-2026-10-28.md)。随后 [第四轮冻结复验](../research/milestones/architecture-round4-2026-10-28.md) 在首个行动来源字段处停止，尚无完整窗口；后续免费修复共用字段定义，不能据此宣布真实选择质量、自然节奏或跨日生活通过。

每个绑定步骤目前只保留少量完成结果根，但绑定条目和联系用途的长期归档、跨版本迁移及运行增长仍需 R3-D 验证。机会目录只描述已实现能力；开放新想法、丰富对话和新地区规律仍需各自的机制设计。共享合同不能代替这些内容，也不能保证模型会作出有趣的选择。
