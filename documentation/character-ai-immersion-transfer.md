# Character.ai 沉浸机制迁移说明

**版本：** v0.1 · 2026-09-16

本文记录对 Character.ai 官方 Creator Guide、Lorebooks、Scene Creation Quickstart 的可迁移设计原则。网页内容可能随服务更新；这里保留的是与 DeskBot 当前架构相容的产品结论，不把第三方页面当作 DeskBot 的实现证明。

## 可迁移的三种机制

### 1. Lorebook：按需注入，而不是把百科全书塞进每一轮

Lorebook 的核心价值是把背景条目绑定到关键词/触发条件，在相关场景出现时才加入上下文。DeskBot 对应为作者维护的 `world_line`、NPC、外部事件和角色方向条目，每条必须有来源、时间、版本和有效期；命中只生成 prompt view，不直接修改世界。这样“聚形域”会在相关时刻出现生活细节，而不是每句话都故弄玄虚。

### 2. Scene：固定开场状态 + 可继续的场景钩子

Scene 不是一段孤立的长提示词，而是角色、地点、当前冲突和用户可介入入口的可复现起点。DeskBot 的故事包采用同一思想：预览时只展示三日步骤；安装后由 scheduler 写入真实世界线，NPC 行动与后果按 canonical mutation 执行，重启继续且不重复。`causal_chain` 让每一步都能回放。

### 3. Greeting / Example dialogue：用示范让功能长在人格里

高质量开场和示例对话规定角色如何在具体任务中说话，而不是只列形容词。DeskBot 的喵呜 seed、roleplay bible 和表达意图合同承担这一层：先完成事实/动作，再用喵呜的口癖、停顿、偏好和明确边界组织同一句话；不能把角色化内容作为功能答案之后的附加尾巴。

## DeskBot 的边界

- 作者条目是背景输入，不是 LLM 可写的 Soul。
- 用户选择最多改变角色方向证据与试行倾向；不能一句话直接换壳或改世界。
- 故事包预览无副作用，安装是显式动作；同一版本幂等，取消不回滚历史。
- 机会和未解钩子必须标明为机会/悬念，不能伪装成已发生事实。
- NPC 先采用有限、作者提供的条件分支；开放规划在有回放和冲突保护前不启用。

## 本轮实现

`/api/life/story-packages` 提供 `GET` 列表，以及 `POST {operation: "preview"|"install", package_id}`。当前内置「潮后寻路：三日共同经历」：潮痕出现、巡路员开放旧路、收摊留下回声。预览不写存档；安装产生四个 canonical 步骤（世界事件、NPC 创建、NPC 行动、世界后果）和证据链。
