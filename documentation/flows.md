# DeskBot 关键流程

**当前功能基线：v0.5 · 角色发展第 6 阶段，2026-10-07。** 本文件说明持续世界、现实输入、角色发展、表达和设备之间如何连接。所有成果与当前阶段以服务端存档为准。

## 持续生活与实际后果

1. 服务以上海现实 1:1 时间校正世界；任务保存真实期限，重启后恢复经过的时间。研究加速使用独立数据库。
2. 喵呜与十二名居民根据食欲、精神、已有任务、关系、兴趣和天气获得有限生活候选。模型可在空闲时参与合法候选选择；基础需要和已有事务仍优先。
3. 选择经过实际路线、通路、材料、容量与设施核验后，生成持续旅行或活动。UI 展示执行中的位置和动作，不先显示完成。
4. 到期结算生产、消耗、交接、失败或取消；共同结果保存因果根。任务、居民项目、记忆和角色发展读取同一份结果。
5. 普通生活、供给与合作继续循环。缺料是现实条件问题，不能自动扣成“不会做”，也不能用模型台词补库存。

## 现实输入折射

1. 固定服务端适配器接收天气、NASA Science RSS 与 Open-Meteo/CAMS 区域空气；主人事件与登记设备输入分别校验。其他 agent 有适配边界，尚无默认连接的外部 agent 服务。
2. `input-runtime` 维护刷新、TTL、持久待投递与失败退避；相同来源事件不会因重启重复进入。
3. 输入保留来源、发布时间或观测时间、收到时间、有效期与作用权限。新闻只作为消息；空气是区域模型，麦克风方向不是身份识别。
4. 合法参考经 `input-refraction` 影响处境和有限候选，例如雨水、露天活动与尚待实践的建议。外部正文不能直接生成物资、建筑或角色阶段。
5. 记忆区分世界事实、他人消息与个人理解。公开 HTTP 事件不能自行声明可信服务端或硬件来源，模型输出也不能循环充当亲历证据。

天气连接器支持 Open-Meteo 和 QWeather。当前工作站使用上海 Open-Meteo；其他部署以实际连接器状态为准。观测进入统一世界入口，预报保存在独立缓存。TTL 到期可后台刷新，主人明确要求最新时才绕过缓存；失败保留带原时间的旧快照。

## 从兴趣到角色阶段

1. 实际任务、项目和关系结果进入共同证据。接触、自主继续、受邀实践、需要、具体表现和规则自评分开记录，同根不重复计数。
2. 原有角色方向达到当前生活前提与冷却后，保存形态或职业愿望和冻结依据。主人可支持、暂缓或拒绝；支持只表示愿意准备。
3. 对已支持的愿望启动实际试做。照料、制作或烹饪进入原自主候选与任务系统，继续核对路线、配方、材料预留、耗时及真实结果。
4. 暂停、调整或退出保留已经发生的后果。准备旅行、取消、聊天回合或条件困难不算主要成功；当前试做方式在当前回顾窗口内、两个上海日期完成两项主要成功才具备成功回顾依据。
5. 读取纯预览，核对原愿望、原试做、`repeated_actual_success` 和当前形态、职业双轴版本。预览不写入世界；确认提交预览指纹，过期依据需要重读。
6. 明确采用后写入唯一 `world.role_stages` 当前轴与历史，封存对应试做。有限生活候选、当前表达、地图与正式 3D 同时读取该版本；采用不赠送材料或技能。
7. 回退指定当前阶段，只恢复对应轴及前一版本，另一轴继续。任务、资源消耗、关系和记忆保留；封存的旧试做不能反复用于采用。

当前选项是荷叶青蛙（形态）、工坊学徒与灶边厨师（职业）。原虚拟识别锚点继续保留；实际壳体、声音和转头能力不随虚拟采用自动改变。规则见 [愿望](../research/world/role-wishes-v1.md)、[实际试做](../research/world/role-practical-trials-v1.md) 和 [阶段](../research/world/role-stages-v1.md)。

| 操作 | 当前接口 |
| --- | --- |
| 查看共同结果与发展维度 | `GET /api/life/development` |
| 查看方向、愿望、试做与阶段 | `GET /api/roles/evolution` |
| 回应已保存愿望 | `POST /api/roles/proposals/:id/choose` |
| 实际试做控制 | `POST /api/roles/proposals/:id/practical-trial/start`，同路径支持 `pause`、`resume`、`adjust`、`exit` |
| 纯阶段预览 | `GET /api/roles/proposals/:id/stage/preview` |
| 明确采用 | `POST /api/roles/proposals/:id/stage/accept`，携带 `preview_fingerprint` |
| 回退当前轴阶段 | `POST /api/roles/proposals/:id/stage/rollback`，携带 `stage_id` |

写接口只接受已登记方式和控制字段，不接受自报成果、任意形象或技能。旧聊天试行接口仅用于兼容历史，不是新世界的愿望与采用入口。

## 文字对话与统一表达

1. 客户端提交 `POST /api/chat`；服务校验消息、身份、事件时间和大小，以 `event_id` 与 fingerprint 防止重复或冲突回合。
2. 服务整理当前世界、短状态、有限对话、来源上下文、记忆、愿望与当前双轴阶段，再交给模型生成答语。
3. 对明确发展与采用状态提问，事实校准读取真实存档；预览不会被说成已经采用，已回退历史不能冒充当前形态。校准范围有限，仍需真实连续对话验收。
4. 同一校准后答语进入屏幕回复、assistant 审计事件、mock TTS 验证与设备文字 outbox。模型原稿只在本地审计中保留，不当作世界成果。
5. outbox 根据设备能力与表达意图生成允许的命令；同一事件与 ACK 重传不重复执行。

模型失败返回结构化错误，不回显上游正文或密钥。DeepSeek 负责语言及有界选择，没有直接修改世界、角色、身份或设备权限的能力。

## 身体感知与设备回执

1. 已登记设备连接 `/ws`，发送 `device.hello`；服务校验绑定、协议、能力和消息大小。匿名 hello 不能自行获得身体权限。
2. 头部触摸、触屏、声音方向与磁识别分别进入身体层。未知壳不猜形态，相对麦阵方位不直接当作绝对转头目标。
3. 感知可以影响注意与空闲候选，不能抢占吃饭、休息、工作与约定，也不能把桌边转头写成虚拟旅行。
4. 受限单轴动作意图经过校准坐标、忙碌、冷却和期限核验后，复用唯一 outbox 发送；设备回传 ACK、失败或过期。
5. 发送、设备报告和实测结果分别保存。当前硬件缺少位置编码器，开环角度报告不能被说成已测量角度。

当前小智固件尚未适配 DeskBot 协议。本软件合同与模拟 WebSocket 回合已验证，真实屏幕、地磁、双麦方向和底座动作留待实机联调。

## 语音管线的当前状态

语音输入合同已区分 partial/final；只有 final transcript 进入一次用户回合。配置 voice sidecar 后，统一答语才交给 TTS，音频工件保存格式、hash 与关联编号，设备据此播放和回执。

当前正式部署未启用真实 sidecar，仓库 worker 为 fake/model-free 边界。真实中文 ASR/TTS、试听、延迟和硬件播放是下一阶段；未配置时接口明确报告不可用。

## 一致性与失败处理

- `event_id` 相同但内容冲突返回 409；阶段预览过期或回退非当前轴也拒绝提交。
- 非法来源、未知世界动作、缺材料、容量或路线条件不会留下部分成果。
- 阶段预览、候选与场景展示不会自行采用阶段或制造行动成果；明确接受才经统一 mutation 与 ledger 写入当前阶段。
- 来源或模型超时保留可解释错误与重试状态；设备失败不改写成成功。
